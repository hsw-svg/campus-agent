# 院校 AI 助手前端开发文档

> 版本：V1.0  
> 编写日期：2026-07-16  
> 依据：《设计方案.md》《开发文档.md》《赛题要求.md》及 `apps/web` 当前实现  
> 适用范围：`apps/web` React 前端开发、联调、测试和比赛演示

## 1. 文档目标

本文将产品设计和后端开发约束转换为可执行的前端方案，明确：

- 页面和交互流程；
- React 组件、Hooks 和 API/SSE 客户端的职责；
- 工作空间、附件、智能体和成果的数据边界；
- 教师 P0 闭环以及学生、行政 P1 能力的前端承载方式；
- 异常、隔离、可访问性和测试验收标准。

前端只负责展示、输入收集、任务编排和状态反馈。路由判断、权限校验、确定性统计、资料筛选和最终业务结果以后端为准，前端不得自行推断或绕过后端约束。

## 2. 需求分析与产品边界

### 2.1 核心用户流程

```text
打开应用
  -> 选择教师/学生/行政角色
  -> 创建或恢复匿名角色工作空间
  -> 进入统一对话工作台
  -> 新建对话或打开历史对话
  -> 上传资料并选择本次任务可用的附件/成果
  -> 输入任务，自动路由或手动确认智能体
  -> 通过 SSE 展示执行过程、回复和 Artifact
  -> 查看引用、重试、导出或继续追问
```

教师比赛演示主线：

```text
上传匿名学情表
  -> 明确选择表格并分析班级整体学情
  -> 生成 Python 数组课堂练习
  -> 生成课堂互动活动包
  -> 输入匿名课堂观察或选项统计
  -> 获得误区、追问和教学动作
  -> 选择活动包和观察记录
  -> 生成并导出课堂总结
```

### 2.2 角色范围

| 角色 | P0/P1 前端能力 | 资料边界 |
| --- | --- | --- |
| 教师 | 学情分析、教案/题目生成、课堂互动；后续作业批改、课程迭代、教学报告 | 只读取教师工作空间；学情任务只允许匿名表格和班级聚合结果 |
| 学生 | 课程资料问答、错题答疑；后续简历、学习规划、口语练习 | 只读取学生主动上传且明确选择的资料，不可见教师和行政资料 |
| 行政 | 会议纪要、待办拆解、通知、摘要、文本规整 | 只读取行政工作空间；结果支持复制和导出，不做系统内推送 |

### 2.3 明确不做

- 不提供注册、登录、账号、班级、选课或师生关系表单；首次使用只选择一次角色。
- 不展示学生个体画像、匿名编号对应的行级分析或原始学生行。
- 不做扫码答题、实时学生端互动、跨角色推送和学生问题回流。
- 不把“文件已上传”当成“当前任务可读取”；资料必须在当前任务中明确选择。
- 不在前端计算成绩、人数、比例、平均分和趋势；这些值必须使用后端确定性结果。

## 3. 技术栈与工程约定

- React 19 + TypeScript；
- Vite；
- Tailwind CSS v4；
- `lucide-react` 图标和 Motion 动效；
- React Hooks 管理工作台状态，当前没有全局状态库；
- Fetch API：普通 JSON 请求和 `fetch` POST + `ReadableStream` SSE；
- Nginx 代理 `/api/`，开发环境使用 Vite 代理；
- 当前没有独立的前端测试脚本，质量检查使用 `npm.cmd run lint` 和 `npm.cmd run build`；
- API 类型和请求封装集中在 `src/api.ts`，组件不得重复声明后端字段。

当前目录：

```text
apps/web/src/
  api.ts                      # API 类型、请求封装、SSE 和导出
  App.tsx                     # 角色入口和工作区路由
  hooks/
    useWorkspaceChat.ts       # 会话资源、选择状态和流式执行
  components/
    RoleSelector.tsx
    ConversationHistory.tsx
    StudentWorkspace.tsx
    AdminWorkspace.tsx
    TeacherWorkspace.tsx
    ClassroomInteractionPanel.tsx
    ArtifactCard.tsx
    ResourcePicker.tsx
  index.css
  main.tsx
```

当前仓库使用 `App.tsx`、`RoleSelector`、三个角色工作区和 `ConversationHistory` 组成页面，使用 `useWorkspaceChat` 管理会话资源与 SSE 流，使用 `api.ts` 统一 API 契约。新增模块应优先复用这些接口，不引入另一套组件格式或全局状态库。

## 4. 页面与布局

### 4.1 角色入口页 `RoleEntryView`

页面内容：

- 项目名称和一句话说明；
- 三个角色卡片：教师、学生、行政；
- 匿名与数据隔离提示；
- 当前角色存在本地凭据时显示“继续进入”，凭据失效时清除并提示原因。

交互规则：

1. 点击角色后调用 `POST /api/workspaces`；
2. 成功后按角色保存匿名 workspace token，并加载智能体和会话列表；
3. 失败时保留角色页，显示后端可读错误；
4. 不出现注册、登录、手机号、班级或身份信息表单。

### 4.2 统一工作台 `WorkbenchView`

桌面端布局：

```text
┌────────────────────────────────────────────────────────────┐
│ 顶栏：当前角色 / 当前工作空间 / 健康状态 / 切换角色       │
├───────────────┬──────────────────────────┬───────────────┤
│ 会话列表       │ 消息流                   │ 资料与任务面板  │
│ 新建、删除      │ 用户消息、助手消息       │ 附件、成果、智能体│
│                 │ 运行状态、引用、Artifact │ 当前任务资料选择│
├───────────────┴──────────────────────────┴───────────────┤
│ Composer：输入框、上传、资料选择、智能体选择、发送/停止   │
└────────────────────────────────────────────────────────────┘
```

窄屏端将左右侧栏改为抽屉或底部面板，消息区始终保持可读；发送中禁止重复发送，但允许停止生成。

### 4.3 工作台组件职责

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| `ConversationHistory` | 列出会话、新建、打开、删除 | 不拼接上下文，不判断智能体 |
| `StudentWorkspace/AdminWorkspace/TeacherWorkspace` | 组织角色工作台、输入、消息、运行状态和结果 | 不在前端执行路由和统计 |
| `ResourcePicker` | 区分工作区资料、当前对话附件和历史 Artifact，维护显式选择 | 不把未选文件偷偷加入请求 |
| `ArtifactCard` | 展示结构化成果、引用、复制和 Markdown/CSV 导出 | 不重新生成或修改成果内容 |
| `useWorkspaceChat` | 管理会话资源、选择 ID、SSE 连接、重试和停止 | 不绕过后端工作空间校验 |
| `api.ts` | 集中 API 类型、请求、SSE 事件和导出下载 | 不保存 React 组件状态 |

## 5. 前端状态模型

### 5.1 核心类型

```ts
type WorkspaceRole = 'teacher' | 'student' | 'admin'
type AgentSelection = 'auto' | string
type AgentRunStatus = 'running' | 'needs_input' | 'failed' | 'completed' | 'retry'
type AttachmentScope = 'conversation' | 'workspace'
type AttachmentStatus = 'uploaded' | 'parsing' | 'indexed' | 'degraded' | 'failed'

interface Workspace {
  id: string
  role: WorkspaceRole
}

interface Agent {
  id: string
  name: string
  description: string
}

interface Conversation {
  id: string
  title: string
  agent_id: string | null
  created_at: string
  updated_at: string
}

interface Attachment {
  id: string
  conversation_id: string | null
  filename: string
  content_type: string
  size_bytes: number
  scope: AttachmentScope
  status: AttachmentStatus
  status_message: string | null
  extracted_chars: number
  created_at: string
  updated_at: string
}

interface RouteDecision {
  run_id: string
  agent_id: string | null
  confidence: number
  reason: string
  missing_inputs: string[]
  selection_source: 'rule' | 'manual' | 'llm' | string
  requires_confirmation: boolean
  candidates: Agent[]
  status: AgentRunStatus | string
}
```

### 5.2 React 状态与 Hooks

当前实现不使用全局状态库。`useWorkspaceChat` 以 workspace token 为边界，集中管理当前角色的会话列表、消息、附件、Artifact、显式附件/成果选择、路由信息、运行状态、SSE 连接、停止和重试；`api.ts` 只负责 API 数据类型和网络请求。

角色选择、token 保存和页面级角色切换由 `App.tsx` 与 `RoleSelector` 协作完成；输入框、抽屉开关、导出错误等短生命周期视图状态保存在对应工作区组件中。组件通过 Hook 返回的状态和回调交互，不能自行拼装上下文或复制请求契约。

状态清理规则：

- 切换角色时清空会话、消息、附件、智能体、成果和运行状态；
- 新建对话时清空当前对话附件、成果和路由确认，不继承其他会话状态；跨会话的工作区资料库继续可见，但不会自动加入任务；
- SSE 完成后重新拉取服务端消息、附件和成果，服务端数据覆盖本地草稿；
- 组件卸载、切换会话或点击停止时中止 `AbortController`，避免旧流写入新会话。

## 6. API 对接契约

所有需要工作空间权限的请求携带 `X-Workspace-Token`。错误统一读取：

```json
{
  "error": {
    "code": "needs_input",
    "message": "请先选择一份匿名学情表",
    "details": { "missing_inputs": ["selected_attachment_ids"] }
  }
}
```

| 方法 | 路径 | 前端用途 |
| --- | --- | --- |
| POST | `/api/workspaces` | 创建匿名角色工作空间，body `{ role }` |
| GET | `/api/workspaces/current` | 校验本地 token 是否仍有效 |
| DELETE | `/api/workspaces/current` | 清空当前角色空间并清理本地凭据 |
| GET | `/api/agents` | 获取当前角色白名单和自动路由 ID |
| POST | `/api/conversations` | 创建会话，body `{ agent_id }` |
| GET | `/api/conversations` | 获取当前工作空间会话列表 |
| GET | `/api/conversations/{id}/messages` | 打开会话时加载历史消息 |
| DELETE | `/api/conversations/{id}` | 删除会话及其关联资源 |
| POST | `/api/conversations/{id}/attachments` | 上传附件，multipart `file + scope` |
| GET | `/api/conversations/{id}/attachments` | 获取当前会话附件状态 |
| POST | `/api/conversations/{id}/route` | 发送前预览路由、缺失输入和确认候选 |
| POST | `/api/conversations/{id}/messages/stream` | 提交消息并接收 SSE |
| POST | `/api/agent-runs/{id}/retry` | 对 failed 任务重试 |
| GET | `/api/artifacts/{id}` | 查看成果详情 |
| GET | `/api/artifacts/{id}/export` | 下载 Markdown/CSV 等导出结果 |

流式请求 body：

```json
{
  "content": "根据本节课目标，生成 Python 数组课堂练习",
  "agent_id": null,
  "selected_attachment_ids": ["attachment-id"],
  "selected_artifact_ids": ["artifact-id"]
}
```

`agent_id: null` 表示自动路由；手动选择只允许 `/api/agents` 返回的当前角色智能体。

## 7. SSE 事件与前端状态机

后端事件类型固定为：`message_start`、`route_decision`、`tool_status`、`artifact`、`delta`、`error`、`done`。其中 `artifact` 的 `data.type=sources` 表示检索引用，不创建成果卡，只更新当前回复的来源列表。

示例：

```text
event: route_decision
data: {"agent_id":"lesson_design","confidence":0.94,"reason":"用户明确要求生成课堂练习","requires_confirmation":false}

event: delta
data: {"text":"## 课堂练习\n"}
```

前端处理规则：

| 事件 | UI 行为 |
| --- | --- |
| `message_start` | 创建助手草稿消息，记录 `run_id` 和最终智能体 |
| `route_decision` | 展示路由标签、置信度和理由；需要确认时打开候选选择 |
| `tool_status` | 更新“解析资料 / 计算统计 / 生成内容”等阶段文案 |
| `delta` | 追加助手文本，保持滚动位置；用户上滑时不强制抢回滚动 |
| `artifact` | 普通 Artifact 挂到消息和成果列表并显示预览/导出；`data.type=sources` 仅更新引用列表 |
| `error` | 标记运行失败或需要输入，展示原因、缺失项和重试入口 |
| `done` | 结束 loading，重新拉取消息、附件、成果，清理流连接 |

状态转换：

```text
idle -> running -> completed
             ├-> needs_input
             ├-> failed -> retry -> running
             └-> stopped（用户主动停止，保留已生成文本）
```

解析器必须支持跨 chunk 的半截事件、多个 `data:` 行和末尾无空行的残留缓冲；网络断开时显示“连接中断”，不得将其误显示为模型生成成功。

## 8. 资料选择与安全隔离

### 8.1 UI 数据分层

界面至少区分三类数据：

1. **工作区资料库**：跨会话可见的 `scope=workspace` 附件；
2. **当前对话附件**：仅当前会话可见的 `scope=conversation` 附件；
3. **当前任务上下文**：本次发送真正传给后端的 `selected_attachment_ids` 和 `selected_artifact_ids`。

附件状态卡只表示上传/解析状态；教师课程任务自动使用当前课程全部资料，学生/行政工作台仍按角色策略显式选择资料。引用来源只展示后端返回的当前 Executor 实际使用资料。

### 8.2 选择规则

- 教师课程任务：自动使用当前课程的全部资料；学情分析由服务端筛选状态可用的表格资料；
- 教案/题目：自动使用课程资料或活动包，默认排除学情明细表；
- 课堂互动：自动使用当前课程资料，活动包、观察和总结仍通过 Artifact 引用；
- 课后总结/教学报告：只选择当前对话明确选中的 Artifact；
- 学生课程问答：只允许明确选择学生空间的课程资料；未选择时由后端返回 `needs_input`；
- 学生个性化答疑：只允许明确选择错题、作业或薄弱点材料，不展示未选材料和学习详情；
- 行政会议纪要/待办：可直接处理当前输入，也可明确选择行政资料，不隐式附加当前上传文件；
- 学生/行政：只能列出当前角色工作空间资源。

教师课程请求可以自动提交当前课程全部附件 ID，最终仍以服务端课程边界和智能体策略校验结果为准；学生/行政请求不能把整个工作区附件列表自动塞入请求。

### 8.3 切换与清理

- 切换角色：立即清空当前 Hook 状态，再加载新角色资源；
- 新建对话：当前对话附件区域为空，不继承旧会话附件和路由证据；工作区资料库仍可见并可被显式勾选；
- 删除会话：从列表移除并回到空白草稿，服务端负责级联清理；
- 清空角色空间：二次确认，成功后删除该角色 token、历史缓存和本地草稿。

## 9. 角色化交互设计

### 9.1 教师 P0

#### 学情分析

输入区提示用户上传并选择匿名成绩/作业/练习表，执行期间展示：文件解析、字段识别、确定性统计、建议生成四个阶段。结果卡包含班级整体统计、趋势、薄弱点、教学节奏建议、字段警告和导出按钮，不显示匿名编号对应画像或原始行。

#### 教案与题目生成

提供主题、教学目标、时长、题型和补充要求输入。若未提供教学目标，明确提示“将按主题生成通用练习”，不得在界面上暗示使用了学情明细依据。结果展示题目、答案、解析、难度、预计用时和可选评分量规。

#### 课堂互动

活动包卡片展示活动序列、时长、题目、误区、分层提示、评分量规和分支动作。观察输入支持自然语言，例如“8 人选 A，21 人选 B，5 人选 C”。当数据存在两组人数、总数不一致或归属不明时，展示确认表单，不自动继续。

#### 课后总结与导出

要求用户选择活动包和观察记录，结果包含课堂摘要、共同误区、教学反思、后续练习和下次课调整项；支持 Markdown/CSV 导出和继续引用。

### 9.2 学生 P1

空工作空间进入后引导上传课程资料、错题或作业。课程问答（`course_qa`）和个性化答疑（`personal_tutor`）使用 `ResourcePicker` 明确选择附件，分别展示答案/要点/追问和诊断/解释/练习建议；结果由 `ArtifactCard` 展示结构化字段与实际来源引用，并支持 Markdown/CSV 导出。

### 9.3 行政 P1

会议纪要（`meeting_minutes`）结果使用结构化卡片展示议题、决议、负责人、截止时间和证据；待办拆解（`todo_breakdown`）展示任务、负责人、截止时间、优先级和证据。两者均支持直接输入或明确选择行政资料，复用 `ArtifactCard` 的 Markdown/CSV 导出，不显示发布或跨角色推送按钮。

## 10. 异常与可恢复交互

| 场景 | 前端表现 | 用户动作 |
| --- | --- | --- |
| token 失效/越权 | 清除对应角色凭据，回到角色页并说明会话已失效 | 重新选择角色 |
| Chat Key 缺失 | 顶部健康提示；确定性学情分析仍可用，生成类任务显示配置错误 | 查看配置说明或切换可用任务 |
| LLM 超时/网络断开 | 保留用户消息和已生成文本，AgentRun 标记 failed | “重试”或继续追问 |
| Embedding 失败 | 附件标记 `degraded`，提示已降级为关键词检索 | 可继续任务或重新上传 |
| 文件解析失败 | 附件卡显示 failed 和可读原因 | 删除后重新上传 |
| 输入不足 | 运行状态为 needs_input，列出缺失字段/资料 | 补充输入后继续，不重复创建无效任务 |
| 路由低置信度 | 展示候选智能体、理由和确认按钮 | 选择候选或取消 |
| 结构化输出无效 | 不显示为成功成果，保留校验错误 | 重试，不下载无效 Artifact |

错误提示至少包含原因、缺失输入或重试入口，禁止只显示 `Request failed`。危险操作（删除会话、清空空间）必须二次确认。

## 11. 视觉、可访问性与响应式要求

- 延续现有绿色/米白视觉变量和 Tailwind CSS 样式，使用 `lucide-react` 图标和 Motion 动效；状态颜色同时配合文字或图标，不能只靠颜色表达；
- 所有按钮、图标按钮、上传控件和弹窗具备可访问名称；

## 15. 任务状态与双栏交互规范

### 15.1 单一运行状态

\`useWorkspaceChat\` 是当前对话工作台的运行状态编排入口。中间消息区和右侧功能区不得分别维护“生成中”状态；两者必须读取同一个 \`run_id\`、\`runStatus\`、\`toolStatus\` 和 \`artifact_id\`。

按钮或快捷入口提交前统一形成：

\`\`\`ts
type RunRequest = {
  intent: string
  courseId?: string
  selectedAttachmentIds: string[]
  selectedArtifactIds: string[]
  params?: Record<string, string>
}
\`\`\`

同一 \`intent\`、课程、资料和参数在已有运行中时，前端应定位已有任务并阻止重复提交。

### 15.2 中间区与右侧区分工

| 区域 | 允许做什么 | 禁止做什么 |
| --- | --- | --- |
| 中间对话区 | 展示消息、路由、时间线和完整 Artifact | 读取右侧组件私有的生成状态 |
| 右侧任务控制台 | 配置参数、显示运行摘要和成果索引；课程任务默认使用全部课程资料 | 再次生成同一任务、重复提供资料选择、完整复制 Artifact |

\`ArtifactCard\` 默认只在中间消息流中渲染。右侧只显示紧凑成果行，并提供查看详情、导出、选择引用和进入下一阶段的操作。

### 15.3 课堂互动面板模式

右侧课堂互动面板包含三个模式，但每个模式只能触发对应阶段：

- **活动包**：配置主题、目标和时长，自动使用当前课程全部资料创建活动包 Run。
- **观察**：输入匿名观察或聚合统计，引用活动包 Artifact，创建观察 Run。
- **总结**：选择活动包和观察 Artifact，创建课后总结 Run。

生成完成后不应在右侧再次展示完整活动包；右侧只更新成果索引和下一步按钮。

### 15.4 课程、对话和成果

课程是跨对话上下文；对话是阶段过程；成果是可引用对象。新建对话时保留课程资料库，但清空当前对话附件、临时勾选、运行状态和草稿成果。跨阶段引用必须通过明确的 Artifact ID 传递，不得扫描全部历史成果。

### 15.5 前端验收

1. 从中间输入和右侧点击生成，最终只创建一个 Run；
2. 两个区域的处理中、完成、失败和停止状态一致；
3. 课堂互动完整内容只展示一次；
4. 右侧成果索引可以选择活动包和观察记录供下一阶段引用；
5. 切换课程或新建对话不会泄漏上一课程的运行状态和临时选择。

### 15.6 P1 CourseContext 与教学闭环

教师工作台通过统一 `CourseContext` 标识当前课程和阶段工作流：

```ts
type CourseContext = {
  courseId: string
  courseName: string
  workflowId: string
  workflowName: string
}
```

每次 `streamMessage` 同时发送 `course_id`、`workflow_id`、`parent_run_id` 和 `input_refs`。
`parent_run_id` 默认取上一条 Run 的 ID，使后续活动包、观察和总结可以沿同一条教学链路追踪；
服务端会校验父 Run 必须属于当前对话。课程上下文是元数据，不等同于账号、权限或课程实体管理。

### 15.7 左侧课程与任务交互

- 主入口文案为“新建任务”，而不是“新建对话”。
- 课程列表以可展开/折叠栏呈现，展开后显示该课程下的任务；底部“任务”列表显示 `course_id = null` 的未关联课程任务。
- “+”创建课程；课程创建后自动成为当前课程，后续新任务默认关联该课程。
- 新任务首次发送前不创建后端 Conversation，保证左侧不会出现空任务。
- `useWorkspaceChat` 按当前 `CourseContext.courseId` 加载课程资料；课程任务默认使用当前课程的全部资料，切换课程时清理成果。
