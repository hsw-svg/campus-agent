# 院校 AI 助手解耦版设计方案 V2

> 状态：当前权威方案
>
> 修订日期：2026-07-16
>
> 本版本在原设计方案基础上，结合赛题要求、阶段 1—6 实现进度和已暴露的问题，补充智能体执行架构、Skill 复用层、上下文资料策略和比赛演示闭环。
>
> 本文维护产品边界、领域模型和架构决策；具体任务状态、验收命令和交付清单以《开发文档 V2》为准。

## 1. 修订结论

本项目不整体迁移 LangChain 或 LangGraph。后端继续使用 FastAPI、SQLAlchemy、Pydantic、统一 LLM Provider、确定性数据处理和工作空间隔离；在智能体执行接口之后预留框架适配 seam。

采用以下原则：

- Agent Router 只负责任务识别和角色内选择，不生成最终业务结果。
- Skill 负责可复用的解析、计算、检索、校验和导出能力。
- AgentSpec 描述智能体的输入契约、上下文策略、Prompt、Skill 和 Executor。
- AgentExecutor 负责一个具体智能体的完整业务执行。
- ContextBuilder 负责资料和历史消息的选择，禁止通用对话服务隐式拼接工作区全部资料。
- 确定性数据由程序计算，LLM 负责解释、生成和自然语言表达。
- LangChain 或 LangGraph 只能作为具体 Executor 的可替换 Adapter，不作为全后端基础依赖。

### 1.1 AI Coding 规范符合性

本项目选择赛题允许的 AI Coding 路径，不声明依赖 OpenClaw 运行时。符合性由以下可审查成果证明：

- 完整源代码、版本化设计文档、阶段任务和回归测试。
- 具有明确输入输出契约的 Skill 和 AgentSpec。
- 可重复执行的构建、测试、部署和演示命令。
- AI 辅助开发产生的设计决策、问题复现和验收记录。
- 提交前根据组委会最终发布的 AI Coding 文本/PPT 模板补齐格式映射；如果官方规范新增强制清单，以官方版本为准。

## 2. 赛题定位与核心范围

赛题要求选取 1—2 项校园智能化核心场景进行开发，同时体现教师、学生、行政岗位的扩展能力。本项目的参赛主线收敛为教师教学闭环：

```text
匿名学情表
  -> 班级整体学情研判
  -> 薄弱知识点与教学节奏建议
  -> 课堂互动活动包
  -> 输入匿名课堂观察或答题统计
  -> 生成追问、练习和即时教学动作
  -> 导出课堂总结
```

教师闭环是 P0 核心场景；学生和行政能力保留角色化底座和轻量演示路径，避免在比赛前分散核心场景的开发和验证资源。

### 2.1 产品目标

- 将教师的学情表整理、统计、薄弱点判断和教学建议生成流程压缩为可追踪的对话任务。
- 根据教学目标、课程资料和班级整体情况生成课堂互动活动包。
- 根据教师输入的匿名课堂观察或聚合统计，提供可解释的讲解、追问和节奏调整建议。
- 让每次智能体调用都有清晰的资料来源、执行状态、错误状态和可导出成果。
- 通过工作空间和上下文策略保证教师、学生、行政三类数据完全隔离。

### 2.2 明确不做

- 不建立登录、账号、班级、选课、师生关系或学生真实身份关联。
- 不从学生端向教师端回流问题、答题记录或画像结果。
- 不实现扫码答题、实时学生端互动或系统内通知推送。
- 不生成学生个体画像；学情分析只输出班级整体统计和教学建议。
- 不让模型负责成绩、人数、比例、平均分等确定性计算。

## 3. 角色与智能体

### 3.1 学生角色

- 课程资料问答：只检索学生主动上传的课程资料。
- 个性化答疑：根据学生上传的错题、作业和自述进行解释。
- 练习助手：生成分层练习、解析和学习建议。
- 简历助手、口语练习、学习规划：作为 P1/P2 扩展能力。

学生端不得读取教师资料、教师学情结果或行政通知。

### 3.2 教师角色

| 智能体 | P0/P1 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 学情分析 | P0 | 明确选择的匿名成绩、作业或练习表 | 班级整体统计、薄弱点、教学方式与节奏建议 |
| 课堂互动 | P0 | 教学目标、课程资料、匿名学情摘要、课堂观察或聚合统计 | 活动包、误区判断、追问、教师提示语、分支动作 |
| 教案与题目生成 | P0 | 教学目标、主题、时长、当前对话资料 | 教案、课堂练习、讨论任务、评分量规 |
| 作业批改 | P1 | 题目、参考答案、学生作答 | 评分建议、评语、错误归因 |
| 课程迭代 | P1 | 教材、旧课件、教学大纲、用户明确选择的学情摘要 | 更新建议和课件草稿 |
| 教学报告 | P1 | 用户明确选择的当前对话成果 | Markdown、CSV 或其他导出报告 |

教师资料默认归教师工作空间。涉及学生数据的智能体只能接收匿名数据和班级聚合结果。

### 3.3 行政角色

- 通知生成与润色
- 会议纪要整理
- 材料摘要
- 待办拆解
- 表格与文本规整
- 公文格式检查

行政结果只支持复制和导出，不在系统内推送给其他角色。

## 4. 领域术语

- **Workspace**：固定角色的匿名工作空间，是所有业务资源的隔离主键。
- **Conversation**：工作空间内的对话和当前任务上下文。
- **Attachment**：用户上传的原始文件及解析状态，不等于当前任务必然可用的资料。
- **MaterialChunk**：附件解析后的文本切块和向量。
- **Skill**：一个可复用、可测试、具有输入输出契约的能力模块。
- **AgentSpec**：一个智能体的完整声明，包括角色、输入契约、上下文策略、Prompt、Skill 和 Executor。
- **AgentExecutor**：执行一个智能体业务任务的模块。
- **AgentRun**：一次路由和执行的状态记录，包含选择来源、置信度、错误、重试和成果状态。
- **Artifact**：可查看、导出和继续引用的结构化成果。

## 5. 总体架构

```text
角色选择
  -> 匿名角色 Workspace
  -> React 对话工作台
  -> Conversation API
       -> Agent Router
       -> Agent Catalog / AgentSpec
       -> ContextBuilder / ContextPolicy
       -> AgentExecutor
            -> Skill Registry
            -> 确定性分析模块
            -> LLM Provider Adapter
            -> 可选 LangChain Adapter
            -> 可选 LangGraph Adapter
       -> AgentRun / Artifact
       -> SSE 流式事件
  -> PostgreSQL + pgvector / Object Storage
```

### 5.1 模块职责

| 模块 | 接口职责 | 不负责的事情 |
| --- | --- | --- |
| Agent Router | 根据角色、任务意图和当前证据返回 RouteDecision | 不读取全部资料生成答案，不执行业务逻辑 |
| Agent Catalog | 注册和过滤 AgentSpec | 不保存执行状态 |
| ContextBuilder | 按智能体策略选择历史、附件、成果和引用 | 不决定调用哪个智能体 |
| AgentExecutor | 校验输入、调用 Skill/LLM、生成 AgentResult | 不直接操作 HTTP/SSE |
| Skill Registry | 提供可复用 Skill 的发现和版本管理 | 不保存会话状态 |
| Conversation Orchestrator | 持久化消息、编排路由和执行、发布 SSE | 不内置任何具体业务分析算法 |
| Artifact Repository | 保存和导出成果 | 不重新推断业务内容 |

这些模块之间通过小接口形成深模块。上层只需要了解请求、结果、状态和错误，不需要知道具体 LLM 或数据库实现。

## 6. Skill 设计

Skill 不依赖 LangChain，采用项目自己的轻量注册方式，以满足赛题对“轻量化智能辅助 Skill”的要求。

### 6.1 基础 Skill

```text
table_parser
  解析 CSV/XLSX，并返回字段、行和解析警告

learning_statistics
  计算出勤、课堂积极性、作业均值、完成率和趋势

classroom_observation_parser
  解析“8 人选 A、21 人选 B”等课堂观察文本

output_validator
  校验结构化活动包、题目、统计和引用来源

artifact_exporter
  将 AgentResult 导出为 Markdown、CSV 或其他支持格式
```

### 6.2 Skill 契约

每个 Skill 必须声明：

- 唯一 ID 和版本
- 输入类型
- 输出类型
- 可预期错误
- 是否有副作用
- 是否允许访问工作空间资料
- 最小单元测试和集成测试

示例：

```python
class Skill(Protocol):
    id: str
    version: str

    def run(self, input: SkillInput) -> SkillOutput:
        ...
```

Skill 应该返回结果，不直接写入会话或发送 SSE；副作用统一交给上层 Executor 和 Repository。

## 7. AgentSpec 与执行接口

### 7.1 AgentSpec

```python
@dataclass(frozen=True)
class AgentSpec:
    id: str
    role: WorkspaceRole
    name: str
    description: str
    system_prompt: str
    input_contract: InputContract
    context_policy: ContextPolicy
    skills: tuple[str, ...]
    executor_id: AgentExecutorId
```

当前 `registry.py` 中的角色白名单继续保留，但必须逐步升级为 AgentSpec 注册表。客户端传入的 `agent_id` 只允许匹配当前角色的白名单。

### 7.2 AgentExecutor

```python
class AgentExecutor(Protocol):
    async def execute(self, request: AgentRequest) -> AgentResult:
        ...
```

`AgentRequest` 至少包含：

- workspace_id
- conversation_id
- user_content
- selected_attachment_ids
- context
- agent_run_id

`AgentResult` 至少包含：

- text
- structured_data
- citations
- artifacts
- warnings
- validation

Executor 不直接依赖 FastAPI 请求对象，不直接生成 SSE，便于单元测试、重试和未来替换执行引擎。

### 7.3 当前智能体执行策略

```text
LearningAnalysisExecutor
  = table_parser + learning_statistics + output_validation + artifact_exporter
  已接入统一 AgentExecutor，继续使用确定性 Python 实现

LessonDesignExecutor
  = ContextBuilder + LLM 生成 + output_validator
  当前可使用 OpenAICompatibleChatProvider

ClassroomInteractionExecutor
  = classroom_observation_parser + 确定性统计
  + ContextBuilder + LLM 解释 + output_validation

CourseQAExecutor / PersonalTutorExecutor
  = selected student materials + Pydantic schema validation + Artifact export

MeetingMinutesExecutor / TodoBreakdownExecutor
  = explicit admin materials or direct content + Pydantic schema validation + Artifact export
```

LangChain 和 LangGraph不进入 AgentSpec 的公共接口，只作为 Executor 内部 Adapter。

## 8. 上下文与资料安全策略

上下文策略是防止本次“课堂练习混入学情资料”问题的核心模块。

### 8.1 ContextPolicy

```python
class ContextPolicy(Protocol):
    def select(self, request: AgentRequest) -> AgentContext:
        ...
```

每个智能体必须声明：

- 可读取的附件范围
- 是否允许工作区级资料
- 是否必须用户明确选择文件
- 可读取的历史消息类型
- 可读取的 Artifact 类型
- 是否允许返回原始行级数据
- 最大上下文长度

### 8.2 资料访问规则

| 智能体 | 默认资料范围 | 特殊限制 |
| --- | --- | --- |
| 学情分析 | 用户明确选择的匿名表格 | 当前上传可以在前端自动勾选，但后端必须收到并校验附件 ID；只输出班级聚合数据 |
| 教案与题目生成 | 当前对话明确选择的课程资料、教学目标和活动包 | 默认排除学情明细表 |
| 课堂互动 | 当前活动包、课程资料、匿名聚合统计和教师观察 | 不读取学生端历史，不猜测未提供人数 |
| 课程迭代 | 当前对话明确选择的教材、旧课件和成果 | 禁止隐式扫描其他会话 |
| 教学报告 | 用户明确选择的当前对话成果 | 不自动合并整个工作区；仍为后续切片 |
| 课程资料问答 | 当前学生工作空间中用户明确选择的课程资料 | 无选择时返回 `agent_input_incomplete`，不可访问教师或行政工作空间 |
| 个性化答疑 | 当前学生工作空间中用户明确选择的错题、作业或薄弱点材料 | 不读取未选择附件和学情明细 |
| 会议纪要 | 行政用户本次输入和明确选择的行政资料 | 无附件时允许直接整理输入，不隐式读取当前上传 |
| 待办拆解 | 行政用户本次输入和明确选择的行政资料 | 负责人、日期、优先级和事实无证据时不补造 |

“文件已上传”不等于“当前智能体可以读取”。附件状态卡、路由证据、检索来源和最终 Prompt 必须使用不同的数据结构，不能互相复用。

### 8.3 学情分析输入规则

学情分析不得依赖 `list_chunks_for_workspace()` 直接扫描全部文件。目标接口为：

```text
用户选择附件
  -> 校验附件归属 workspace
  -> 校验文件状态和表头
  -> 只读取 selected_attachment_ids
  -> 生成班级整体 Artifact
```

工作区范围上传仅解决跨会话可见性，不改变“当前任务需要明确选择资料”的原则。

## 9. 路由设计

路由器遵循以下优先级：

1. 当前角色可用智能体白名单。
2. 用户明确表达的输出任务意图。
3. 当前消息显式选择的附件及其表头。
4. 当前对话最近消息和已确认的智能体状态。
5. LLM 结构化分类。
6. 低置信度时要求用户确认。

显式任务意图优先于附件偶然证据。例如：

```text
“根据本节课目标生成课堂练习，Python 数组”
  -> lesson_design

“分析这份匿名成绩表，判断班级薄弱章节”
  -> learning_analysis
```

如果用户曾经手动选择过智能体，当前智能体状态只能作为短期会话提示，不能永久覆盖新的明确任务意图。

路由决策统一返回：

```json
{
  "agent_id": "lesson_design",
  "confidence": 0.94,
  "reason": "用户明确要求生成课堂练习",
  "missing_inputs": [],
  "selection_source": "rule",
  "requires_confirmation": false
}
```

## 10. 对话执行流程

```text
接收消息
  -> 校验 workspace 和 conversation
  -> 生成 RouteContext
  -> AgentRouter.route()
  -> 创建 AgentRun
  -> AgentCatalog.resolve()
  -> ContextBuilder.build()
  -> AgentExecutor.execute()
       -> Skill / 确定性模块 / LLM Adapter
       -> 输入和输出校验
  -> 保存 Message / Artifact / Citation
  -> 发布 SSE
```

Conversation Orchestrator 只负责流程和状态，不负责拼接业务 Prompt，也不直接实现学情、课堂互动或批改算法。

## 11. 确定性计算与 LLM 分工

### 程序负责

- 表格解析和字段映射
- 人数、比例、平均分和趋势
- 数据校验和匿名编号检查
- 选项统计总数校验
- 活动时长和评分量规约束
- 权限、工作空间和附件归属校验
- Artifact 持久化和导出

### LLM 负责

- 任务意图识别
- 课堂误区解释
- 教学建议表达
- 活动设计和练习生成
- 结构化内容的自然语言组织

LLM 输出必须经过 Pydantic 或等价结构校验。无效项可以被丢弃，但必须报告丢弃原因。

## 12. 数据模型与隔离

所有业务表必须带 `workspace_id`，Repository 默认按工作空间过滤：

- anonymous_workspace
- conversation
- message
- attachment
- material_chunk
- agent_run
- artifact
- teacher_interaction_record

资源按 ID 查询时必须同时校验 `workspace_id` 和角色。对象存储路径必须包含工作空间隔离层。删除工作空间时级联删除会话、附件、向量、任务和成果。

学生匿名编号只存在于教师上传的数据字段中，不与任何学生工作空间或身份表关联。

- `artifact`
- `delta`
- `error`
- `done`

## 14. 本地部署与异常处理

部署目标：

- Docker Compose 启动数据库、API 和 Web 三个服务。
- `.env.example` 明确列出 Chat、Embedding 和数据库配置。
- 模型 Key 缺失时显示可读错误，不阻塞本地学情确定性分析。
- 文件解析失败、Embedding 失败、LLM 超时和结构化输出错误均保留任务状态，并支持重试。
- Embedding 不可用时降级为当前工作空间内的关键词检索。

## 15. 赛题演示主线

1. 进入教师角色，不登录。
2. 上传匿名 Python 课程学情表。
3. 自动识别并执行班级整体学情分析。
4. 展示出勤率、课堂积极性、作业趋势、薄弱点和教学节奏建议。
5. 输入“根据本节课目标，生成 Python 数组课堂练习”。
6. 验证任务路由到教案与题目生成，且不显示学生明细和学情表来源。
7. 生成课堂互动活动包。
8. 输入匿名课堂观察，例如“8 人选 A，21 人选 B，5 人选 C”。
9. 输出确定性比例、共同误区、追问和教师提示语。
10. 导出课堂总结。
11. 切换学生角色，验证教师资料和成果不可见。
12. 切换行政角色，演示会议纪要和待办拆解。

## 16. 验收标准

### 核心功能

- 匿名学情表字段校验、班级聚合统计和教学建议正确。
- 课堂练习任务不会被学情文件错误路由到学情分析。
- 教案与题目生成不会读取学情明细表。
- 课堂观察的人数和比例由程序计算，LLM 不补造数据。
- 活动包包含目标、时长、题目、解析、误区、评分量规和分支动作。

### 安全隔离

- 三类角色空间两两隔离。
- 伪造 `agent_id` 不能调用其他角色智能体。
- 枚举资源 ID 不能读取其他工作空间。
- 学情分析不输出匿名编号对应的学生行级内容。
- 新建对话不会继承上一对话的附件路由证据和资料来源。

### 工程质量

- 每个 P0 智能体有 Executor、输入契约、上下文策略和回归测试。
- 路由、上下文选择、数据解析和输出校验可以在没有真实模型 Key 时测试。
- Docker Compose 可一键启动，文档和演示数据完整。
- 不出现真实学校、班级、教师、学生或联系方式。

### 界面与交付

- 首次进入最多经过一次角色选择即可开始对话，不要求注册或填写身份信息。
- 上传、智能体选择、资料选择、执行状态和导出操作在统一对话工作台完成。
- 路由确认、输入不足、解析失败和模型错误均提供中文可读提示和下一步操作。
- 交付物包含完整源代码、一键部署教程、功能演示视频成片、演示数据和组委会要求的文本/PPT。

## 17. 框架决策

### 保留自研的部分

- FastAPI API 和 SSE
- SQLAlchemy Repository
- Workspace 隔离
- Attachment 解析与资料策略
- 学情确定性统计
- AgentRun 和 Artifact 状态
- Pydantic 业务结果校验

### 可局部采用 LangChain 的部分

- 需要多个 Tool Calling 的 Executor
- 统一模型和结构化输出适配
- 复杂 RAG 适配器
- Prompt Middleware 和模型切换

### 可局部采用 LangGraph 的部分

- 课堂互动多步骤活动包生成
- 课程迭代的资料对齐、草稿生成和审核流程
- 教学报告的人工确认、失败恢复和断点续作

全量引入 LangChain/LangGraph 会增加依赖、状态和调试复杂度，当前不作为 P0 任务。

## 18. 教学工作台交互模型：单任务源与双视图

### 18.1 核心层级

系统必须区分角色、课程、教学闭环、对话、任务 Run、智能体和 Artifact：

\`\`\`text
角色空间
  -> 课程上下文
    -> 教学闭环
      -> 阶段对话
        -> AgentRun
          -> Artifact
\`\`\`

- **角色**只决定可用能力和数据边界，不等同于当前智能体。
- **课程**保存主题、教学目标、课程资料和课程成果，不等同于一段聊天记录。
- **对话**记录用户与系统的过程，可按备课、学情研判、课堂互动、课后复盘分型。
- **AgentRun**代表一次真实执行，是中间区和右侧面板共同观察的唯一状态源。
- **Artifact**代表一次结构化成果，完整内容只保留一个权威展示位置，其他区域只显示引用和操作入口。

### 18.2 单任务源、双视图

中间对话区负责任务叙事：用户请求、智能体、执行时间线和完整 Artifact。

右侧功能区负责任务控制：课程上下文、资料选择、参数配置、运行摘要、成果索引和下一步操作。右侧不得再次创建同一任务，也不得完整复制中间的 Artifact。

按钮触发和自然语言触发都必须归一为同一个 \`RunRequest\`，由 \`run_id\` 关联：

\`\`\`text
intent + course_id + selected_resource_ids + params_hash
  -> 复用 running Run 或创建新的 AgentRun
\`\`\`

### 18.3 教师教学闭环

教师 P0 主线采用四阶段：

\`\`\`text
学情研判 -> 课堂活动包 -> 课堂观察 -> 课后总结
\`\`\`

每一阶段创建独立 Run，并通过 \`input_refs\` 明确引用上一阶段 Artifact。原始学情明细不得自动进入课程设计、课堂互动或课后总结。

### 18.4 多智能体编排边界

路由智能体只负责确定目标智能体和输入缺口；领域智能体负责具体业务；解析、统计、校验和导出作为可复用 Skill。复杂任务内部可以有多个步骤，但默认只向用户展示一个领域智能体和一个最终 Artifact。

该设计借鉴 OpenMAIC 的“结构化课程大纲 -> 教学场景”的两阶段生成思路，但不引入学生实时通信。OpenMAIC 官方资料说明其通过多智能体编排生成幻灯片、测验、模拟实验和项目活动；本项目仍遵循赛题的教师单端课堂观察边界。
