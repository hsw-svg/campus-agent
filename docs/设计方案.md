# 院校 AI 助手解耦版设计方案

> 状态：新项目的当前权威方案。原仓库 `docs/` 下的文档为第一版教学闭环方案，仅作历史参考。

## 1. 目标与边界

系统改造成无登录、无账号、无班级、无师生绑定的多角色 AI 助手。用户首次进入时选择学生、教师或行政角色，随后直接进入类似 GPT 的对话工作台。

三个角色只共享 LLM、文件解析、RAG、任务状态和导出等技术底座，不共享业务数据：

- 不共享会话、附件、知识库、分析结果和历史记录。
- 不建立课程归属、选课、班级、学号或师生关系。
- 不从学生端向教师端回流问题，也不从教师端向学生端下发资料或学情结果。
- 切换角色时进入独立工作空间，不能搜索或引用其他角色空间的数据。
- 用户可在当前角色中主动上传外部文件，但系统不提供跨角色同步、转发或自动导入。

“完全解耦”指角色业务数据在系统内没有通信路径。各角色调用同一后端 AI 服务不属于角色之间通信。

## 2. 产品交互

### 2.1 首次进入与角色切换

首次打开系统只展示学生助手、教师助手和行政助手三个入口。选择后立即创建匿名角色工作空间并进入对话页，不要求用户名、密码、手机号、学号或真实姓名。

浏览器分别保存三个角色的随机工作空间凭据。凭据只用于找回本机历史，不表达用户身份，也不能访问其他角色空间。切换角色时必须同时切换工作空间、会话列表、智能体列表和文件索引，禁止沿用上一角色的对话上下文。

### 2.2 GPT 式对话工作台

- 左侧：新建对话、历史对话、角色切换和设置。
- 中间：消息流、流式回复、引用来源、生成结果和继续追问。
- 输入区：文本输入、文件上传、停止生成、重新生成。
- 智能体入口：默认“自动识别”，也可以手动选择具体智能体。
- 结果操作：复制、下载 Markdown/CSV、保存为当前角色的本地成果。

首屏直接进入可操作的对话界面，不设置登录页、注册页或营销页。

## 3. 角色智能体

### 3.1 学生角色

- 课程资料问答：上传教材、讲义或课件后进行 RAG 问答。
- 个性化答疑：根据本人上传的错题、作业和自述薄弱点进行解释。
- 练习助手：生成分层练习、解析答案和学习建议。
- 简历助手：分析简历、改写经历、生成模拟面试问题。
- 口语练习：围绕指定场景进行对话、纠音和表达建议。
- 学习规划：根据本人输入的目标、时间和学习记录生成计划。

学生端不得读取教师资料、教师学情结果或行政通知。学校通知只能通过外部门户链接查看，或者由学生自行粘贴、上传后让 AI 解读。

### 3.2 教师角色

- 作业批改：上传题目、参考答案和学生作答，生成评分建议与评语。
- 学情分析：上传匿名成绩、作业或练习表，生成统计、薄弱点和教学建议,为班级整体情况，不对单个学生做具体分析。
- 课堂互动助手：生成互动方案，分析教师输入的课堂现象或答题统计，给出下一步教学动作。
- 课程迭代：上传教材、旧课件、教学大纲和学情文件，生成更新建议与课件草稿。
- 教案与题目生成：生成教案、互动题、讨论任务、评分量规和课后练习。
- 教学报告：汇总教师工作空间中由用户明确选择的材料并导出报告。

教师上传的学生数据必须使用匿名编号；这些编号不与任何学生工作空间对应。

### 3.3 行政角色

- 通知生成与润色
- 会议纪要整理
- 材料摘要与要点提取
- 待办拆解
- 表格和文本规整
- 公文格式检查

行政端生成的通知不会在系统内推送到学生端或教师端，只支持复制和文件导出，由用户通过既有办公系统发布。

## 4. 自动识别与手动选择

每条新任务默认经过角色内智能体路由器：

1. 根据当前角色过滤可用智能体，绝不跨角色选择。
2. 提取文本、文件类型、文件表头和最近对话上下文。
3. 先用确定性规则识别明显任务，例如成绩表、简历、会议记录。
4. 规则无法确定时调用 LLM 输出结构化分类结果。
5. 高置信度时直接调用目标智能体；低置信度时展示候选项，请用户确认。
6. 回复中显示“已调用：学情分析助手”等运行标识，并允许重新选择。

```json
{
  "agent": "learning_analysis",
  "confidence": 0.91,
  "reason": "附件包含匿名编号、章节、得分和满分字段",
  "missing_inputs": []
}
```

路由器只决定调用哪个智能体，不生成最终业务结果。用户手动选择智能体后跳过分类，但目标智能体仍需校验输入是否充分，不能在缺少材料时虚构分析。

## 5. 课堂互动智能赋能

### 5.1 能力边界

完全不通信后，系统不能获得学生端实时答题，也不能形成“学生反馈回流教师”的自动闭环。因此课堂互动定义为教师单端的课堂决策助手，而不是在线答题平台。

数据来源仅包括：

- 教师上传的课程资料、习题和教学目标。
- 教师上传的匿名成绩或作业统计。
- 教师在对话中手工输入的课堂问题、举手情况、选项人数、典型回答和现场观察。
- 教师从学校已有教学工具导出的匿名统计文件。

### 5.2 课前模式

教师输入教学主题、目标、时长和学生基础，AI 生成“课堂互动活动包”：

- 诊断题、选择题、判断题、讨论题和案例任务。
- 每项活动的目的、预计用时和组织方式。
- 常见错误答案及其对应误区。
- 分层提示、参考答案和评分量规。
- 不同课堂反馈下的教学分支建议。

### 5.3 课中模式

教师通过自然语言持续输入课堂现象，例如：“这道题 8 人选 A，21 人选 B，5 人选 C，大部分学生解释不清独立与互斥的区别。”

系统结合当前对话中的活动包和课程资料输出：

- 答题分布的确定性统计。
- 可能的共同误区及证据。
- 立即讲解、同伴讨论、追加追问或切换案例的建议。
- 一道可直接投屏的追问题。
- 建议用时和教师提示语。

人数、比例和得分由程序计算，LLM 只负责解释。教师未输入的数据不得由模型补造。

### 5.4 课后模式

系统根据教师明确选择的当前对话内容生成课堂互动摘要、知识误区、教学策略反思、后续练习和下次课调整项。结果只保存在教师工作空间，不生成学生画像，也不向学生端发送。

## 6. 核心数据模型

所有业务表必须带 `workspace_id`，仓储层默认按工作空间过滤，禁止仅凭资源 ID 查询记录。

| 对象 | 作用 |
| --- | --- |
| `anonymous_workspace` | 保存固定角色、匿名凭据摘要和活动时间 |
| `conversation` | 保存工作空间内的对话标题、当前智能体和上下文摘要 |
| `message` | 保存消息、工具调用、引用资料和结构化结果 |
| `attachment` | 保存附件元数据、解析和索引状态 |
| `material_chunk` | 保存带工作空间边界的文本切块和向量 |
| `agent_run` | 保存路由结果、智能体类型、状态、错误和成果 ID |
| `artifact` | 保存报告、教案、活动包、简历建议和会议纪要等成果 |
| `teacher_interaction_record` | 保存教师输入的课堂观察、匿名聚合数据、AI 分析和建议动作 |

`teacher_interaction_record` 不包含学生账号、学号或学生端问题 ID。

## 7. API 轮廓

```text
POST   /api/workspaces                         创建匿名角色工作空间
GET    /api/workspaces/current                 校验当前工作空间
GET    /api/agents                             获取当前角色可用智能体
POST   /api/conversations                      新建对话
GET    /api/conversations                      获取当前空间历史
GET    /api/conversations/{id}/messages        获取消息
POST   /api/conversations/{id}/attachments     上传附件
POST   /api/conversations/{id}/route           仅执行智能体识别
POST   /api/conversations/{id}/messages/stream 自动路由或指定智能体并流式回复
POST   /api/agent-runs/{id}/retry               重试失败任务
GET    /api/artifacts/{id}                     获取成果
GET    /api/artifacts/{id}/export              导出成果
```

请求通过匿名工作空间凭据确定 `workspace_id` 和固定角色。客户端传入的角色、工作空间 ID 和资源归属均不可信。

## 8. 技术架构

```text
角色选择
  -> 匿名角色工作空间
  -> GPT 式对话界面
  -> Conversation Service
       -> 角色内 Agent Router
       -> Student / Teacher / Admin Agents
       -> Shared Skills
       -> LLM Provider + JSON Guard
       -> Workspace-scoped RAG Retriever
       -> Artifact Export
  -> PostgreSQL + pgvector / Local Object Storage
```

继续沿用 Vue 3、FastAPI、PostgreSQL + pgvector、统一 LLM Provider、结构化 JSON 校验、任务状态和本地对象存储。删除 JWT 登录和角色账号体系，但保留不可猜测的匿名工作空间凭据作为数据隔离能力。

## 9. 安全与异常处理

- 工作空间凭据至少使用 128 位随机值，数据库只保存摘要。
- 每次资源访问同时校验工作空间和角色，防止枚举 ID 越界读取。
- 文件路径包含工作空间隔离层，下载接口不暴露真实路径。
- 删除工作空间时级联清理会话、附件、向量和成果。
- 表格中的姓名、手机号等字段应提示匿名化；演示数据不得包含真实学校和人员信息。
- 路由置信度低时要求确认，不静默调用不相关智能体。
- LLM、embedding 或解析失败时保留对话和附件，记录失败状态并允许重试。
- embedding 不可用时只在当前工作空间内降级关键词检索。

## 10. 明确删除的第一版能力

- 登录、注册、账号管理、JWT 角色授权。
- 班级、选课和师生关系。
- 学生问题自动同步到教师问题看板和跨学生问题聚类。
- 教师学情结果自动用于学生练习推荐。
- 教师资料自动出现在学生课程问答中。
- 行政通知在系统内推送到学生端。
- 学生扫码参与教师课堂活动或任何实时跨端互动。

这些能力不能以隐藏账号、设备 ID 或后台关联表的方式变相保留。

## 11. 演示主线

1. 首次进入选择教师，不登录，直接进入对话。
2. 上传课程资料和匿名成绩表，系统自动识别“学情分析助手”。
3. 展示字段校验、统计结果、薄弱点和教学建议。
4. 继续说“为这两个薄弱点设计 20 分钟课堂互动”，生成活动包。
5. 模拟输入“8 人选 A、21 人选 B、5 人选 C”，分析误区并给出追问题。
6. 导出课堂互动总结或教学报告。
7. 切换学生角色，展示独立空工作空间，上传个人错题后自动答疑。
8. 手动切换简历助手或口语练习，展示显式智能体选择。
9. 切换行政角色，粘贴会议记录，自动识别并生成纪要和待办。

第 7 步应特意展示教师资料和会话不可见，以证明完全解耦。
