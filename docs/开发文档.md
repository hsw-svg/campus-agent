## 2. 当前问题清单

### P0：必须在继续阶段 7 前解决

1. 智能体注册表目前主要是名称和角色白名单，所有智能体尚无独立 Executor；学情分析已有确定性业务函数，但尚未迁移到统一 Executor 接口。
2. `stream_assistant_reply()` 同时承担路由、检索、业务分支、状态、SSE 和持久化，职责过重。
3. 路由证据、附件状态和模型执行资料边界不清，曾导致课堂练习被学情表影响。
4. 工作区附件会参与跨会话检索，但缺少智能体级 ContextPolicy。
5. 学情分析当前兼容扫描工作区资料，多个表格可能被错误合并；目标必须改为明确附件 ID。
6. 手动选择的当前智能体具有粘性，可能覆盖后续消息中的明确新任务意图。
7. “Skill”目前只是能力概念，尚未形成可注册、可测试、可组合的代码接口。
8. `.env.example` 当前存在非空模型凭据风险；必须立即轮换已暴露凭据，示例文件只保留空占位，真实 Key 仅放入不提交的 `.env` 或部署密钥存储。

### P1：核心闭环完成后解决

1. 教学报告和课程迭代必须使用用户明确选择的成果和资料。
2. 课堂互动需要结构化输出校验和部分失败保留机制。
3. 学生课程问答、行政会议纪要需要独立 Prompt、输入契约和资料策略。
4. Artifact 导出格式需要统一。
5. 前端需要显示当前任务实际使用的资料，而不是工作区全部文件。

## 3. 技术栈与框架决策

### 3.1 固定技术栈

- 前端：Vue 3、Vite、TypeScript、Element Plus、Pinia、Vue Router。
- 后端：Python 3.11+、FastAPI、Pydantic、SQLAlchemy 2.0、Alembic。
- 数据库：PostgreSQL 16 + pgvector。
- 文件存储：本地对象存储接口，预留 MinIO/S3 Adapter。
- 表格与文档：pandas、openpyxl、python-docx、PyMuPDF。
- 模型：OpenAI 兼容 LLM Provider，Chat 与 Embedding 分开配置。
- 部署：Docker Compose，Nginx 代理 API/SSE。

### 3.2 LangChain/LangGraph 决策

- P0 不整体迁移 LangChain 或 LangGraph。
- 先建立项目自己的 AgentExecutor、ContextPolicy 和 Skill 接口。
- LangChain 只允许作为模型、Tool Calling 或结构化输出 Adapter。
- LangGraph 只允许作为复杂多步骤 Executor 的内部实现。
- AgentRun 继续是项目任务状态的唯一事实来源；如果未来使用 LangGraph，其 checkpoint 必须与 AgentRun 建立单向映射，不能形成两套业务状态。

## 5. V2 实施顺序

### 阶段 6A：建立 Agent 执行接口

目标：让“路由到了哪个智能体”和“真正执行了哪个业务模块”一致。

任务：

- 新增 `AgentRequest`、`AgentResult`、`InputContract`。
- 新增 `AgentExecutor` Protocol。
- 将当前角色注册表升级为 AgentSpec 注册表。
- AgentSpec 声明角色、Prompt、输入契约、上下文策略、Skill 和 Executor。
- 新增 `AgentExecutorRegistry.resolve(role, agent_id)`。
- 保留旧注册表兼容接口，完成调用方迁移后删除重复定义。

最小接口：

```python
class AgentExecutor(Protocol):
    async def execute(self, request: AgentRequest) -> AgentResult:
        ...
```

验收：

- `learning_analysis` 和 `lesson_design` 能解析到不同 Executor。
- 客户端伪造其他角色 `agent_id` 被拒绝。
- Executor 单元测试不依赖 FastAPI、SSE 或真实模型 Key。

### 阶段 6B：建立轻量 Skill 层

目标：将可复用的解析、计算、校验和导出能力显式注册为赛题要求的 Skill。

任务：

- 建立 Skill Protocol 和 Skill Registry。
- 将表格解析与字段识别迁移为 `table_parser`。
- 将出勤、课堂积极性、作业趋势迁移为 `learning_statistics`。
- 建立 `output_validation` 和 `artifact_exporter`。
- Skill 返回数据和错误，不直接写会话或发送 SSE。

验收：

- Skill 声明 ID、版本、输入、输出和错误。
- 学情统计在无 LLM 配置时仍可独立运行。
- 同一个导出 Skill 可被学情分析和课堂总结复用。

### 阶段 6C：建立 ContextBuilder

目标：从架构上隔离路由证据、附件状态、检索资料和模型 Prompt。

任务：

- 新增 ContextPolicy 和 ContextBuilder。
- 请求支持 `selected_attachment_ids` 和 `selected_artifact_ids`。
- 附件 Repository 增加按工作空间和附件 ID 列表读取的方法。
- 学情分析只读取明确选择的匿名表格。
- 教案与题目生成默认排除学情明细表。
- 课程迭代和教学报告只读取用户明确选择的资料和成果。
- 非学情智能体不继承学情分析的行级来源和专属消息。
- 新建对话不继承其他对话的上传状态和路由证据。

验收：

- 上传学情表后请求“生成 Python 数组课堂练习”，路由为 `lesson_design`。
- 模型 Prompt 和引用来源中不包含匿名学生行或学情明细文件。
- 明确请求“分析学情”时，同一工作区表格可被用户选择并成功分析。
- 同一工作区多个表格不会被隐式合并。

### 阶段 6D：拆分 Conversation Orchestrator

目标：让对话模块只编排，不内置业务算法。

目标执行流程：

```text
validate request
  -> route
  -> create AgentRun
  -> resolve AgentSpec
  -> build context
  -> execute agent
  -> persist message/artifact
  -> emit SSE
```

任务：

- 将 AgentRun 创建和更新封装成单一模块。
- 将 SSE 事件生成封装成事件 Adapter。
- 将学情分析特殊分支迁移到 `LearningAnalysisExecutor`。
- 将通用模型调用迁移到 `GenericChatExecutor`。
- 保持现有 API 路径和前端 SSE 协议兼容。

验收：

- `stream_assistant_reply()` 不再包含任何学情字段、表格算法或具体智能体分支。
- API 回归测试继续通过。
- AgentRun 的 running、needs_input、failed、completed、retry 状态保持一致。

## 6. 阶段 6E：迁移教师基础智能体

### 6.1 LearningAnalysisExecutor

输入：

- 一个或多个用户明确选择、且属于当前教师工作空间的匿名表格。
- 可选的分析补充要求。

处理：

- 校验匿名编号和禁止字段。
- 映射出勤、课堂积极性、作业和满分字段。
- 计算班级整体统计、趋势和薄弱点。
- 生成只面向教学方式和节奏的建议。

输出：

- Markdown 文本。
- `scope=class` 的结构化数据。
- Artifact。
- 字段校验警告。

禁止：

- 输出单个匿名编号对应的画像。
- 合并未选择的工作区表格。
- 把原始学生行放入 SSE 来源。

### 6.2 LessonDesignExecutor

输入：

- 教学主题、目标、时长和题型要求。
- 当前对话明确选择的课程资料或活动包。
- 可选的班级整体学情摘要，不允许读取明细表。

输出：

- 课堂练习、参考答案、解析、难度和预计用时。
- 可选教案、互动题、讨论任务和评分量规。

验收：

- “Python 数组课堂练习”生成列表/数组相关题目。
- 回答不展示学情表文件名、匿名编号或行级摘录。
- 如果未提供教学目标，智能体明确使用用户主题生成通用练习，不伪造学情依据。

### 6.3 作业批改、课程迭代和教学报告

列为 P1：

- 作业批改需要题目、参考答案和作答输入契约。
- 课程迭代只使用明确选择的教材、旧课件、教学大纲和学情摘要。
- 教学报告只汇总明确选择的 Artifact。

## 7. 阶段 7：教师单端课堂互动助手

### 7.1 活动包生成

输入：

- 教学主题
- 本节课目标
- 总时长
- 课程资料
- 可选班级整体学情摘要
- 补充要求

输出结构：

- 活动序列和预计用时
- 诊断题、选择题、判断题、讨论题或案例任务
- 参考答案与解析
- 常见错误和误区映射
- 分层提示和评分量规
- 不同课堂反馈下的教学分支动作

校验：

- 选择题必须有合法选项和唯一答案。
- 判断题必须有明确答案。
- 开放题必须有评分要点。
- 活动总时长不能超过教师输入的总时长。
- 无效题目可被丢弃，但必须保留合法题目并报告原因。

### 7.2 课堂观察分析

输入示例：

```text
这道题 8 人选 A、21 人选 B、5 人选 C，
大部分学生解释不清列表索引与切片的区别。
```

处理：

1. `classroom_observation_parser` 提取选项人数和教师观察。
2. 后端计算总人数和比例。
3. 验证数据是否唯一、完整和自洽。
4. 将结构化统计、活动上下文和允许使用的资料交给 LLM。
5. 输出共同误区、下一步动作、追问题和教师提示语。

存在两组人数或归属不明确时，返回确认状态，不猜测题目对应关系。

### 7.3 课后总结

教师从当前对话中明确选择活动包和观察记录，生成：

- 课堂摘要
- 共同误区
- 教学策略反思
- 后续练习
- 下次课调整项

验收主线：

```text
生成活动包
  -> 输入模拟统计
  -> 输出追问和教学动作
  -> 生成后续练习
  -> 导出课堂总结
```

## 8. 阶段 8：学生最小智能体

P1 优先实现两个可演示 Executor：

- CourseQAExecutor：只检索学生当前工作空间明确选择的课程资料。
- PersonalTutorExecutor：只使用学生上传的错题、作业和自述薄弱点。

验收：

- 新建学生工作空间为空。
- 即使同一浏览器已有教师资料，学生检索也无法命中。
- 不使用教师学情结果生成学生推荐。

随后补充轻量角色能力：

- ResumeHelperExecutor：输出问题清单、修改建议、改写稿和模拟面试问题，不伪造经历。
- StudyPlannerExecutor：只根据学生主动提供的目标、时间和学习记录生成计划。
- SpeakingPracticeExecutor：文本对话为 P2，语音识别和合成不进入比赛核心路径。

这些智能体可以复用 GenericChatExecutor，但必须有独立 AgentSpec、Prompt、输入契约和 ContextPolicy，不能只注册名称。

## 9. 阶段 9：行政最小智能体

P1 实现：

- MeetingMinutesExecutor
- TodoBreakdownExecutor
- NoticeWriterExecutor
- SummaryExecutor
- TextCleanupExecutor

要求：

- 自动识别和手动指定共用同一执行路径。
- 输出支持 Markdown 和 CSV 待办。
- 不实现通知发布和跨角色推送。
- 会议记录、纪要和待办只属于当前行政工作空间。
- 通知、摘要和文本规整使用独立输出契约；涉及事实的数据不得由模型补造。

验收：

- 会议记录可生成议题、决议、负责人和待办 CSV。
- 通知生成结果可复制和导出，但系统内没有发布或推送入口。
- 材料摘要和文本规整只读取当前行政工作空间明确选择的资料。

## 10. 阶段 10：隔离和数据生命周期

任务：

- 审计所有 Repository：按 ID 查询必须带 `workspace_id`。
- 对 Conversation、Attachment、Chunk、AgentRun、Artifact 做跨空间越权测试。
- 对象存储按工作空间划分命名空间，下载只通过受控接口。
- 实现删除单个会话、清空角色空间和级联清理。
- 检查 AgentSpec、ContextPolicy 和 Executor 不能跨角色读取资源。
- `student_no` 只作为教师上传表中的匿名业务字段。
- 全仓不得出现账号、JWT、班级、选课或跨角色关联表。

验收：

- 三类空间两两隔离。
- 枚举资源 ID、伪造角色或智能体均不能访问其他空间数据。
- 新建对话不会显示其他对话的附件状态卡。
- 引用来源只显示当前 Executor 实际使用的资料。

## 11. 阶段 11：异常、部署与比赛交付

### 11.1 异常处理

- Chat Key 缺失：显示配置错误；确定性学情分析仍可运行。
- LLM 超时：AgentRun 标记 failed，保留用户消息并支持重试。
- Embedding 失败：标记 degraded，降级为工作空间内关键词检索。
- 文件解析失败：附件状态标记 failed，显示可读原因。
- 结构化输出无效：报告校验错误，不保存为成功 Artifact。
- 输入不足：AgentRun 标记 needs_input，返回缺失输入清单。

### 11.2 部署交付

- `docker compose up -d --build` 一键构建并启动。
- `.env.example` 不包含真实 Key，但列出全部必需配置。
- 提交前执行凭据扫描；发现非空示例 Key、历史泄漏或误提交时必须先轮换凭据，再清理仓库和构建产物。
- 提供环境检查、健康检查和日志排查说明。
- 提供演示数据、部署教程、功能截图、视频脚本和最终功能演示视频成片。
- 演示数据不得包含真实学校、教师、学生或联系方式。
- 按组委会统一文本/PPT模板提交对应材料；提交前核对最新 AI Coding 规范清单。

## 12. 测试策略

### 12.1 单元测试

- AgentRouter：显式任务意图、角色白名单、低置信度确认。
- ContextPolicy：允许/拒绝的附件、历史和 Artifact。
- Skill：表格解析、统计、课堂观察解析、输出校验。
- Executor：输入不足、成功结果、结构化错误和引用来源。

### 12.2 API 集成测试

- 自动路由和手动选择共用执行路径。
- 学情分析成功生成 Artifact。
- 工作区附件可被用户选择，但不会自动污染新对话。
- 课堂练习不会读取学情明细。
- AgentRun 可以重试且不跨工作空间。
- Artifact 获取和导出按工作空间隔离。

### 12.3 前端测试

- 新建对话附件列表为空。
- 工作区资料库和当前上传状态分开显示。
- SSE 事件按顺序更新消息、任务状态和 Artifact。
- 路由确认、输入不足和模型错误可读。
- 切换角色后会话、文件和成果全部切换。
- 首次进入只需选择一次角色即可开始任务，不出现注册、账号或班级信息表单。
- 上传、资料选择、智能体确认、执行状态和导出在统一对话工作台内完成。
- 常见错误提示包含原因、缺失输入或重试入口，不只显示 `Request failed`。

## 13. 比赛演示与评分指标

| 演示步骤 | 证明能力 | 评分对应 |
| --- | --- | --- |
| 教师上传匿名学情表并自动分析 | 学情研判、表格解析、确定性统计 | 场景适配性、功能实用性 |

## 14. 优先级与完成定义

### P0：比赛核心闭环

- AgentSpec / AgentExecutor / ContextPolicy / Skill Registry
- 学情分析迁移和明确附件选择
- LessonDesignExecutor
- ClassroomInteractionExecutor
- 课堂观察解析和确定性统计
- 课堂总结导出
- 空间隔离和上下文隔离回归测试
- Docker Compose 稳定部署

### P1：多岗位扩展证明

- 作业批改
- 课程迭代
- 学生课程资料问答
- 学生错题答疑
- 行政会议纪要和待办
- 教学报告和更多导出格式

### P2：增强项

- 语音口语练习
- 复杂课件导出

LangChain/LangGraph 不列入比赛功能任务。只有当已实现的 Executor 出现多 Tool 循环、人工中断或断点恢复需求，并通过独立技术验证后，才新增对应 Adapter 任务。

### 完成定义

一个智能体只有同时满足以下条件才算完成：

- 已注册 AgentSpec。
- 有独立 Executor。
- 有输入契约和 ContextPolicy。
- 所有确定性数据由程序计算。
- 输出经过结构化校验。
- 引用来源可追踪且不越权。
- 有成功、输入不足、异常和隔离测试。
- 可以通过统一 AgentRun 状态和 SSE 协议执行。

不再规划：学生反馈回流、教师问题看板、跨端推荐、系统内通知推送和在线课堂扫码答题。
