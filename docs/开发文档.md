# 院校 AI 助手解耦版开发路线

> 本文是 `设计方案.md` 的实施计划，面向一个全新项目，从项目骨架开始建设，不继承旧项目的数据库、账号体系或页面结构。

## 1. 技术栈与建设原则

固定技术栈：

- 前端：Vue 3 + Vite + TypeScript + Element Plus、Pinia、Vue Router。
- 后端：Python 3.11+、FastAPI、Pydantic、SQLAlchemy 2.0、Alembic。
- 数据库：PostgreSQL 16 + pgvector。
- 文件存储：本地对象存储接口，预留 MinIO/S3 适配器。
- 表格与文档：pandas、openpyxl、python-docx、PyMuPDF。
- 模型：OpenAI 兼容 LLM Provider，chat 与 embedding 分开配置。
- 部署：Docker Compose，前端由 Nginx 托管并代理 API/SSE。

建设原则：

- 从第一天起不创建 user、账号、登录、JWT、班级、选课或师生关系。
- 所有业务资源必须归属于匿名工作空间，并在仓储层强制隔离。
- 先完成可贯穿全系统的对话主链路，再逐个增加智能体。
- 数字由确定性程序计算，LLM 负责分类、解释和内容生成。
- 每个阶段都包含可独立演示的验收路径，不依赖尚未完成的后续阶段。

## 2. 阶段 1：项目骨架与基础设施

- 创建前后端目录、配置管理、统一错误格式和日志基础。
- Docker Compose 先启动 PostgreSQL + pgvector，配置 Alembic 初始迁移。
- 实现 `/api/health`，分别报告数据库、chat 模型和 embedding 配置状态。
- 定义 LLM Provider、Embedding Provider、`json_guard` 和统一任务错误类型。
- 定义 ObjectStorage 接口及本地实现，业务代码不直接拼接文件路径。
- 建立后端单元测试、集成测试和前端组件测试命令。

验收：前后端可启动，数据库 migration 可执行，健康检查可读，未配置模型时返回明确状态而不是启动失败。

## 3. 阶段 2：匿名角色工作空间

- 新增 `anonymous_workspace` 表和仓储。
- `POST /api/workspaces` 接收角色，返回一次性明文凭据；数据库只保存哈希。
- 创建 `get_current_workspace` 依赖，从请求头读取凭据并返回固定角色。
- 浏览器为学生、教师、行政分别保存凭据。
- 工作空间不存在或凭据失效时重新进入角色选择，不出现登录提示。
- 增加工作空间删除和本地历史清理能力。

测试：凭据随机性、哈希校验、不同工作空间互相返回 404、客户端伪造角色无效。

## 4. 阶段 3：角色选择与统一对话壳

- 实现首次角色选择页，不创建登录和注册入口。
- 实现 `ConversationShell`：会话侧栏、消息区、输入区、附件按钮、智能体选择器。
- 新增 conversation/message API 和前端 store。
- 流式协议包含 `message_start`、`delta`、`tool_status`、`artifact`、`done`、`error`。
- 角色切换时重新加载对应工作空间并清空上一角色的内存上下文。

验收：三个角色均可无登录新建对话、刷新恢复本角色历史，切换后不显示前一角色内容。

## 5. 阶段 4：附件与工作空间 RAG

- 在对话输入区实现统一附件入口。
- attachment/material_chunk 增加 `workspace_id` 和 `conversation_id` 或知识库 ID。
- 解析 txt、md、docx、pdf、xlsx、csv；扫描版 PDF 明确提示。
- Retriever 强制按工作空间过滤，再按会话或知识库过滤。
- 用消息卡展示上传、解析、索引、降级和失败状态。
- 用户可选择“仅用于本次对话”或“保存到本角色资料库”。

验收：相同关键词在不同角色空间检索，只能命中各自上传的文件。

## 6. 阶段 5：角色内智能体路由器

- 建立角色到智能体的白名单注册表。
- 规则路由使用附件 MIME、表头、关键词和对话状态。
- 无法确定时调用 LLM，结构化输出 agent、confidence、reason、missing_inputs。
- 高置信度直接执行，低置信度返回候选智能体要求确认。
- 手动选择通过 `agent_id` 传入，并记录 `selection_source=manual`。
- agent_run 保存路由、执行、重试和成果状态。

验收：成绩表路由到教师学情分析、简历路由到学生简历助手、会议记录路由到行政纪要；任何角色均不能路由到其他角色智能体。

## 7. 阶段 6：教师基础智能体

- 学情分析实现表格导入、字段映射、课程画像和教师工作空间归属。
- 作业批改支持题目、答案和作答三个附件或合并文档，先抽取结构再批改。
- course 只作为教师空间内的可选知识库，不表达学校课程归属或师生关系。
- 课程迭代只使用教师在当前对话中选择的文件和成果。
- 教学报告由当前对话中显式选择的成果生成，避免隐式跨会话拼接。

数字继续由 pandas 或确定性程序计算，LLM 不负责算术。

## 8. 阶段 7：教师单端课堂互动助手

### 8.1 互动活动包

输入教学主题、目标、时长、资料、匿名学情和补充要求，输出活动序列、预计用时、题目、解析、讨论提示、评分量规、常见错误与误区映射、不同反馈下的分支动作。

Pydantic 校验选择题选项、判断题答案、开放题要点、活动总时长和来源引用。部分题目无效时保留合法题目并报告丢弃原因。

### 8.2 课堂观察分析

支持自然语言输入，例如“8 人选 A、21 人选 B、5 人选 C”，也支持教师从既有工具导出的匿名 CSV/XLSX 聚合结果。

后端先解析人数和选项，计算比例并验证总数，再把结构化统计、活动上下文和资料证据交给 LLM。LLM 返回误区判断、建议动作、追问题和教师提示语。

解析不确定时必须展示识别结果并要求确认。例如文本出现两组人数时，不能猜测哪组属于当前题目。

### 8.3 课后总结

教师从当前对话中显式选择活动包和观察记录，生成课堂摘要、误区、反思、练习和下次调整项。不得读取学生角色历史。

验收：演示“生成活动包 → 输入模拟统计 → AI 建议追问 → 导出总结”，全程没有学生端请求和数据关联。

## 9. 阶段 8：学生智能体

- 课程资料问答和个人错题答疑只检索学生自己的附件。
- 练习生成和学习计划只根据学生主动提供的信息。
- 简历助手输出问题清单、修改建议和改写稿，不伪造经历。
- 口语练习先完成文本 MVP，语音识别和合成作为增强项。
- 学习记录是匿名学生工作空间的历史，不含学号或教师评价。

验收：新建学生空间为空；同一浏览器已有的教师资料也无法搜索或引用。

## 10. 阶段 9：行政智能体

- 会议纪要、通知、摘要、待办和格式检查以工具形式注册。
- 自动识别与手动指定共用执行路径。
- 输出支持 Markdown、纯文本和 CSV 待办。
- 不实现系统内通知发布或向其他角色推送。

## 11. 阶段 10：隔离加固与数据生命周期

- 审计全部 Repository，任何按 ID 查询都必须同时带 `workspace_id`。
- 文件、向量、对话、任务和成果分别执行跨空间越权测试。
- 对象存储按工作空间划分命名空间，下载只通过受控 API。
- 实现删除单个会话、清空角色空间和级联清理向量/文件。
- `student_no` 仅可作为教师上传表中的匿名业务字段，不与任何身份表关联。
- 角色智能体注册表采用白名单，客户端伪造 `agent_id` 必须被拒绝。
- 全仓检查不得出现登录、注册、Bearer JWT、用户表、班级表或跨角色外键。

验收：三类空间两两隔离；枚举资源 ID、伪造角色或智能体均不能访问其他空间数据。

## 12. 阶段 11：异常、部署与演示

- Docker Compose 保留数据库、后端和前端三服务。
- 本地启动后直接进入角色选择。
- 准备教师资料、匿名成绩表、课堂观察文本、个人错题、虚构简历和行政会议记录。
- API Key 缺失、LLM 超时、embedding 失败和文件解析失败均显示可读状态并允许重试。
- 强制演示教师上传资料后切换学生，验证学生端不可见。
- 全项目不得出现真实学校、班级、教师或学生信息。

## 13. 优先级

P0：匿名工作空间、统一对话壳、附件、流式回复、角色内路由、教师学情分析、课堂互动助手、空间隔离测试。

P1：作业批改、课程迭代、学生资料问答、简历助手、行政规整、成果导出。

P2：语音口语练习、复杂课件导出、可信联网参考、更多办公格式。

不再规划：学生反馈回流、教师问题看板、跨端推荐、系统内通知推送、在线课堂扫码答题。
