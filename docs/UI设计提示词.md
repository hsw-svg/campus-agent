# 院校 AI 助手 UI 设计提示词

> 版本：V1.0  
> 用途：用于 Figma AI、v0、Lovable、Bolt、Cursor UI 生成或设计师视觉执行  
> 依据：院校 AI 助手设计方案、开发文档、前端开发文档和竞赛演示要求

## 1. 使用说明

下面的“总提示词”用于一次性生成产品视觉方向和核心页面；“页面级提示词”用于逐页生成或迭代；“验收约束”用于检查 AI 生成结果是否偏离产品边界。

生成时必须保留产品名称、角色和功能边界，不要把产品设计成普通的聊天机器人、校园门户、教务管理系统或社交平台。

## 2. 总提示词（推荐直接使用）

```text
请为“院校 AI 助手 Campus Agent”设计一套高完成度、可落地、适合 AI Coding 竞赛现场演示的 Web UI。产品面向高校教师、学生和行政人员，采用匿名角色工作空间，不提供登录、注册、账号、班级、选课、师生关系或真实身份信息表单。核心产品不是普通聊天机器人，而是“统一对话工作台 + 角色化 AI 智能体 + 明确资料选择 + 可追踪任务状态 + 可导出结构化成果”。

一、产品定位和关键场景

首要演示场景是教师教学闭环：
1. 进入教师角色；
2. 上传匿名学情表；
3. 选择本次任务要使用的匿名表格，分析班级整体出勤、课堂积极性、作业完成率、均分趋势和薄弱点；
4. 根据本节课目标生成 Python 数组课堂练习；
5. 生成课堂互动活动包；
6. 输入“8 人选 A、21 人选 B、5 人选 C”等匿名课堂观察；
7. 计算比例并给出共同误区、追问、教师提示语和即时教学动作；
8. 选择活动包与观察记录，生成并导出课堂总结。

学生和行政角色作为同一工作台中的扩展能力出现：学生可进行课程资料问答、错题答疑；行政可整理会议纪要、拆解待办、起草通知和摘要。三类角色的会话、资料、成果必须完全隔离，界面要让这种隔离可见、可理解、可演示。

二、总体视觉方向

关键词：可信、克制、专业、温和、清晰、教学工作台、数据安全、AI 协作、校园场景、可解释。

不要使用赛博朋克、霓虹渐变、过度科技感、机器人头像、夸张 3D、社交信息流、游戏化勋章或营销落地页风格。界面应该像一间现代高校教师的数字备课室：有秩序、有纸张和资料的质感，但仍然体现 AI 的效率。

整体采用浅色背景和高对比内容卡片：暖白纸面、浅灰绿工作区、深墨绿色文字、森林绿主色、少量蓝色表示教师分析、琥珀色表示行政整理、玫瑰色表示错误或风险。使用轻微网格、纸张、文件夹、表格和时间轴隐喻，但不要使用真实学校 logo、校徽或现实身份信息。

建议色板：
- 页面背景：#EEF3F0；
- 卡片背景：#FBFDFB；
- 主文字：#182322；
- 次级文字：#6B7A76；
- 边框：#D9E4DF；
- 主森林绿：#176448；
- 深森林绿：#0F4937；
- 淡薄荷绿：#DFF3E9；
- 教师分析蓝：#3B6F8F；
- 行政琥珀：#AA7132；
- 错误玫瑰：#AE4F54。

字体使用现代中文无衬线字体，优先 Microsoft YaHei UI、PingFang SC、Noto Sans CJK SC 或 Source Han Sans SC。标题要有清晰层级，正文 14–16px，辅助文字不低于 12px。整体圆角 12–16px，阴影柔和克制，不要大面积玻璃拟态。

三、信息架构

产品采用“角色入口页 + 统一对话工作台”两段式结构，不为教师、学生、行政分别制作完全不同的应用。

1. 角色入口页：选择教师、学生或行政；展示匿名空间、安全隔离说明和角色能力简介。
2. 工作台：顶部角色和空间信息；左侧会话列表；中间消息和任务执行区；右侧资料/成果/智能体面板；底部输入与上传区。
3. 角色切换：使用明确的“切换角色”入口，切换前提示当前空间和资料不会与新角色共享。
4. 会话切换：会话列表只显示当前角色工作空间的会话；新建会话后附件和任务选择状态为空。

四、核心工作台布局

桌面端以 1440×900 为主要设计稿尺寸，采用三栏布局：

- 左栏宽度约 248px：产品标识、当前角色徽标、新建对话、会话搜索、会话列表、删除会话。
- 中栏宽度约 680–760px：对话标题、消息流、助手任务状态、Markdown 回复、图表/结构化成果和引用来源。
- 右栏宽度约 300–340px：当前智能体、工作区资料库、当前对话附件、当前任务资料选择、成果列表。
- 底部输入区固定在中栏底部：多行输入框、附件按钮、资料选择按钮、智能体选择按钮、发送按钮；生成中变成“停止生成”。

顶部栏要显示：当前角色（教师/学生/行政）、匿名工作空间状态、模型/服务健康状态、帮助入口、切换角色。不要显示虚构姓名、学校名称、班级名称或头像。

消息流需区分用户消息和 AI 消息，但不使用夸张头像。AI 消息顶部显示“当前调用：学情分析 / 教案与题目生成 / 课堂互动”等任务标签；生成过程中显示轻量进度而不是无限旋转图标。

五、必须设计的页面和状态

请至少生成以下页面/状态，并保持同一套视觉系统：

1. 角色选择页
   - 三张角色卡：教师、学生、行政；分别用教学、学习、行政文档的抽象线性图标；
   - 卡片包含角色名称、适用任务、3 条能力标签；
   - 页面显眼位置说明“无需注册，选择角色即可开始”；
   - 页面底部显示“每个角色拥有独立匿名工作空间，资料不会跨角色共享”；
   - 卡片 hover、点击中、创建成功、创建失败状态；
   - 不显示登录框和手机号输入框。

2. 教师空白工作台
   - 中间显示欢迎引导和三条快捷任务：分析学情、生成课堂练习、生成课堂互动；
   - 右侧显示“教师资料库为空”空状态，并提供上传入口；
   - 输入框上方提供教师常用提示词示例；
   - 视觉重点是帮助教师快速开始，不要出现复杂控制台。

3. 教师学情分析流程
   - 上传 CSV/XLSX 文件后的附件卡：文件名、文件类型、大小、解析状态、字段校验提示；
   - 工作区资料库和当前任务资料选择分开；
   - 选择匿名学情表后显示“本次任务将使用 1 份资料”；
   - 执行状态按阶段展示：解析资料 → 识别字段 → 计算班级统计 → 生成教学建议；
   - 结果卡分为：班级概览、趋势、薄弱点、教学节奏建议、数据警告、引用来源、导出；
   - 只显示班级聚合数据和教学建议，不显示匿名编号对应的个人画像、原始学生行或隐私字段。

4. 教案与题目生成
   - 输入主题、教学目标、课时、题型和补充要求；
   - 支持“根据本节课目标，生成 Python 数组课堂练习”的快捷模板；
   - 结果以题目卡片展示题干、答案、解析、难度和预计用时；
   - 支持“复制题目”“继续生成”“导出”；
   - 如果未提供教学目标，明确显示“按主题生成通用练习”，不要伪造基于学情的结论。

5. 课堂互动活动包
   - 用时间轴或步骤卡展示活动序列、预计用时、诊断题、选择题、判断题、讨论题和案例任务；
   - 每个活动展示目标、教师提示语、参考答案、常见误区、分层提示和评分量规；
   - 顶部显示“总时长不超过教师设定值”的校验状态；
   - 无效题目被丢弃时显示可展开的校验说明，但保留合法活动；
   - 活动包可作为后续课堂观察和课后总结的可选 Artifact。

6. 课堂观察输入和分析
   - 提供自然语言输入框和结构化统计辅助入口；
   - 示例占位符：“这道题 8 人选 A、21 人选 B、5 人选 C，大部分学生解释不清列表索引与切片的区别。”；
   - 先展示程序计算的总人数和比例，再展示 AI 对共同误区、追问、下一步动作和教师提示语的解释；
   - 若存在两组人数、总数不一致或选项归属不明确，显示“需要确认”状态，不自动猜测。

7. 课后总结与导出
   - 使用资料选择器选择活动包和观察记录；
   - 结果展示课堂摘要、共同误区、教学策略反思、后续练习、下次课调整项；
   - 支持 Markdown 和 CSV 导出，导出按钮显示格式和文件名；
   - 展示“本成果引用了哪些资料”，但不显示未经当前任务选择的工作区资料。

8. 学生工作台
   - 视觉延续统一工作台，但快捷任务改为课程问答、错题答疑、学习规划；
   - 空状态引导上传课程资料、错题或作业；
   - 右侧资料面板明确显示“学生工作空间”，不能出现教师资料入口；
   - 提供“资料仅在当前学生空间可见”的安全提示。

9. 行政工作台
   - 快捷任务改为整理会议纪要、拆解待办、起草通知、摘要材料；
   - 会议纪要结果使用议题、决议、负责人、截止时间、待办表格；
   - 提供 Markdown/CSV 导出和复制按钮；
   - 不提供“发布通知”“推送给教师/学生”等按钮。

10. 异常状态集合
   - token 失效；
   - Chat Key 未配置；
   - LLM 超时；
   - Embedding 失败并降级为关键词检索；
   - 文件解析失败；
   - 输入不足；
   - 路由置信度低需要确认；
   - 结构化输出校验失败；
   - 网络断开和用户主动停止生成。

六、资料和隐私交互

设计一个清晰的“当前任务资料”面板，至少分成三组：

1. 工作区资料库：跨当前角色会话可见，但默认不代表本次任务会读取；
2. 当前对话附件：仅当前会话可见；
3. 已选任务资料：真正传给当前智能体的附件和成果。

每项资料显示：名称、类型、状态、更新时间、来源范围、是否已选。使用勾选框或“添加到任务”按钮，已选资料显示绿色标识。上传完成后不要自动把所有资料加入当前任务；可提供“建议选择”但必须允许用户取消。

在资料面板中增加简短说明：“文件已上传 ≠ 本次任务已使用”。这是产品安全和竞赛演示的重要卖点。

七、智能体选择和路由确认

输入区提供“自动识别”作为默认模式，同时允许手动选择当前角色白名单中的智能体。手动选择不应永久锁定后续任务，用户明确表达新任务时仍由后端重新判断。

低置信度时使用内联确认卡，而不是打断式复杂弹窗：

- 标题：“我理解你可能想做以下任务”；
- 展示 2–3 个候选智能体；
- 展示每个候选的简短理由；
- 提供“使用此助手”“重新描述任务”“取消”按钮；
- 显示缺失输入，例如“请先选择一份匿名学情表”。

八、任务状态视觉规范

使用带文字的状态标签、图标和进度线，不要只用颜色：

- running：绿色进行中，显示当前阶段；
- needs_input：琥珀色，需要用户补充资料或字段；
- failed：玫瑰色，展示原因和重试；
- degraded：灰蓝色，显示降级能力和影响；
- completed：绿色完成，显示成果和导出；
- stopped：中性灰，显示用户已停止并保留已生成内容。

SSE 流式生成时，文本逐步出现，右上角显示任务标签和运行时长；用户滚动到历史位置时不得自动抢回滚动。生成结束后统一刷新消息、附件和 Artifact，避免页面只停留在临时草稿。

九、组件和交互细节

- 按钮主次分明：主按钮只保留一个，如“发送”“生成”“导出”；
- 删除会话和清空角色空间使用二次确认，说明会删除的内容；
- 文件上传支持拖拽和点击，显示可接受类型和大小限制；
- Markdown 支持标题、列表、表格、代码块、复制代码和一键复制全文；
- 表格在移动端允许横向滚动，不压缩到不可读；
- 图表只用于班级整体统计和趋势，不创建个体画像图；
- 引用来源使用折叠列表，展示文件名、资料类型和短摘录；
- 空状态需要给出下一步行动，不只显示“暂无数据”；
- 所有错误提示包含原因、缺失输入或恢复入口，不显示孤立的“Request failed”。

十、响应式和无障碍

请同时输出桌面端 1440×900、平板端 1024×768、移动端 390×844 三种布局。

- 桌面端：三栏工作台；
- 平板端：左右栏可折叠，中间消息区优先；
- 移动端：单栏消息区，侧栏改为抽屉，资料和智能体改为底部抽屉；
- 输入区在移动端固定在底部，但不能遮挡键盘和消息；
- 触控目标不小于 44×44px；
- 所有图标按钮有 aria-label；
- 键盘可完成角色选择、上传、资料勾选、路由确认、发送、停止和导出；
- 颜色对比符合 WCAG AA；状态同时通过文字、图标和边框表达；
- 遵循 prefers-reduced-motion，减少非必要动画。

十一、交付物要求

请输出：

1. 设计 Token：颜色、字体、间距、圆角、阴影、状态；
2. 组件库：按钮、输入框、上传卡、附件状态、消息气泡、任务状态、资料选择器、路由确认、Artifact 卡、错误提示；
3. 角色入口页高保真稿；
4. 教师 P0 全流程高保真稿；
5. 学生和行政工作台变体；
6. 移动端响应式稿；
7. 空、加载、成功、失败、需要输入、降级、停止和权限失效状态；
8. 关键交互说明和前端开发标注；
9. 可用于比赛演示的 5 分钟操作路径。

十二、必须避免的问题

- 不要生成登录页、注册页、账号中心、班级管理、教务排课、通知推送或社交评论；
- 不要把教师、学生、行政资料混在同一个列表里；
- 不要默认把整个工作区资料发送给模型；
- 不要在非学情任务中展示匿名学生行、匿名编号或学情明细文件名；
- 不要让模型结果看起来像确定性统计，统计数字需要标明来源和程序计算；
- 不要用一个全屏 loading 覆盖整个应用，任务应在消息流中可追踪；
- 不要让 UI 只展示“AI 正在思考”，要展示解析、计算、生成、校验等可理解阶段；
- 不要依赖真实学校、教师、学生姓名和联系方式，演示数据全部使用匿名或虚构数据。

请以产品级高保真 Web 应用标准输出，确保视觉有院校场景的可信度，操作路径足够短，且能在竞赛现场清楚证明：AI 能理解教学任务、资料使用边界清晰、确定性数据可靠、任务过程可追踪、成果可以沉淀和导出。
```

## 3. 页面级提示词

### 3.1 角色入口页

```text
设计“院校 AI 助手”的匿名角色选择首页，面向高校教师、学生和行政人员。页面不要出现登录、注册、手机号、学校名称或真实姓名。使用浅灰绿色背景、暖白主卡片、森林绿主色和轻微网格纹理。顶部左侧放置简洁产品标识“Campus Agent”，右侧放置“匿名空间 · 数据隔离”状态胶囊。

页面中央是简洁有呼吸感的欢迎区域：小字“校园智能工作台”，大标题“让每一次教学、学习与协作，都更清晰”，副标题说明“选择一个角色即可开始，无需注册”。下方横向排列三张角色卡：教师、学生、行政。每张卡包含抽象线性图标、角色名、描述、三条能力标签和“进入工作空间”隐性按钮。教师卡使用蓝绿色，学生卡使用森林绿，行政卡使用琥珀色，但整体风格统一。

页面底部展示三项安全承诺：匿名使用、角色隔离、资料可控。设计 hover、点击 loading、创建失败和本地空间已存在四种状态。移动端改为纵向卡片。视觉要专业、温和、可信，不要像 SaaS 营销页。
```

### 3.2 教师工作台

```text
设计 1440×900 的高校教师 AI 教学工作台。布局为左侧会话栏、中间对话区、右侧资料与任务面板，底部固定消息输入区。当前角色为“教师”，当前空间标识为“匿名教师空间”。

左侧显示“新建对话”、搜索框和历史会话；中间顶部显示“教学智能工作台”和当前任务状态；右侧上部是“当前助手：自动识别”，下部是资料分组“工作区资料库”“当前对话附件”“本次任务已选资料”。底部输入框上方放三个快捷任务按钮：“分析学情”“生成课堂练习”“设计课堂互动”。

空状态文案应体现教师场景，例如“上传一份匿名学情表，先看看班级整体情况”，并提供上传按钮和三个教学提示词模板。页面中不要放学生姓名、班级管理和教务系统字段。使用清晰的卡片、文件标签、状态徽标和轻微分隔线，避免复杂仪表盘。
```

### 3.3 学情分析结果

```text
设计教师上传匿名 XLSX 学情表并完成分析后的对话结果。中间消息区先显示用户任务和一条可折叠的执行时间线：解析资料、识别字段、计算统计、生成教学建议。完成后显示结构化结果卡，而不是一大段无层次文本。

结果卡顶部是“班级整体学情分析”，带绿色完成状态和“已使用 1 份资料”标签。第一行显示四个聚合指标：出勤率、课堂参与度、作业完成率、平均分趋势；第二部分用简单条形图或趋势线展示班级级别变化；第三部分列出薄弱知识点和教学节奏建议；第四部分显示数据校验警告和引用来源。

禁止显示学生姓名、真实学号、匿名编号对应的个人画像、原始数据行或未经选择的资料。右上角提供“导出 Markdown”“继续生成课堂练习”。视觉上突出数据可靠、建议可执行和来源可追踪。
```

### 3.4 课堂互动活动包

```text
设计“课堂互动活动包”结构化结果页。教师已经输入主题、目标和总时长。使用垂直时间轴展示活动顺序，每个活动卡包含：活动名称、预计用时、教学目标、题型、题目内容、参考答案、常见误区、教师提示语和分层提示。

顶部显示总时长校验条，例如“总计 38 分钟 / 45 分钟”，绿色表示通过。活动卡使用不同但克制的图标区分诊断题、选择题、讨论题和案例任务。卡片支持折叠，默认展开第一个活动。底部提供“输入课堂观察”“生成后续练习”“导出活动包”。

若部分题目无效，显示琥珀色提示“已跳过 1 项无效题目”，点击可查看原因；合法活动必须保留。不要设计实时学生扫码、答题排行榜或弹幕。
```

### 3.5 课堂观察分析

```text
设计课堂互动中的“观察分析”状态。页面上半部展示当前活动和题目，下半部是教师观察输入区，提供自然语言输入和可选的结构化选项统计表。输入示例为“8 人选 A、21 人选 B、5 人选 C，大部分学生解释不清列表索引与切片的区别”。

提交后先展示确定性统计：总人数 34、A 23.5%、B 61.8%、C 14.7%，再展示 AI 解释区：共同误区、建议追问、下一步教学动作、教师可以直接说出的提示语。两组统计冲突时不要猜测，显示中性黄色确认卡并要求教师选择对应活动。

结果页支持“生成后续练习”和“加入课后总结”。强调这是班级聚合观察，不显示个人答题记录。
```

### 3.6 课后总结与导出

```text
设计教师课后总结 Artifact 页面。右侧或顶部先显示资料选择摘要：“活动包 · 课堂观察 · 共 2 项”，允许修改选择。正文分为课堂摘要、共同误区、教学策略反思、后续练习、下次课调整项五个区块。每个区块可以复制，整体支持导出 Markdown 和 CSV。

页面应明确显示“本成果引用资料”，只列出当前任务明确选择的活动包和观察记录。导出成功显示文件格式和文件名；导出失败保留内容并提供重试。整体视觉像可提交的教学复盘文档，不要像聊天气泡。
```

## 4. 竞赛演示视觉检查清单

在评审现场，设计需要让以下能力一眼可见：

- 角色选择无需注册，三类角色入口清楚；
- 教师主流程 5 分钟内可完成，快捷任务和示例输入足够明显；
- 上传、解析、选择资料、路由、执行、生成成果每个状态都有反馈；
- 资料面板能证明“已上传”和“本次已使用”是两件事；
- 学情结果只有班级聚合数据，隐私边界清晰；
- 课堂观察先给程序统计，再给 AI 解释；
- Artifact 有查看、继续引用、复制和导出入口；
- 模型失败、输入不足和网络异常不会让页面失去上下文；
- 切换学生角色后，教师资料和成果不可见；
- 页面截图在 1440×900 和 390×844 下均完整、可读、无横向溢出。

## 5. 设计验收标准

### 必须满足

- 视觉系统统一，颜色、字体、圆角、按钮和状态标签可沉淀为 Design Token；
- 核心工作台具备空、加载、流式、成功、需要输入、失败、降级、停止和权限失效状态；
- 角色、会话、资料、智能体和成果层级清楚；
- 资料选择和引用来源可追踪，未选择资料不会在 UI 中被暗示为已使用；
- 所有关键操作具有明确反馈和恢复路径；
- 组件可映射到 React + Tailwind CSS + `lucide-react` + Motion 实现，不依赖不可实现的复杂动效；
- 关键操作满足键盘操作、焦点可见和颜色对比要求。

### 不合格表现

- 只有一个大输入框和“AI 正在思考”，看不出任务和资料边界；
- 把三类角色做成三个完全割裂的产品；
- 把工作区全部文件自动展示为模型引用；
- 用个体排行榜、真实学生资料或班级管理增强所谓“校园感”；
- 生成结果没有结构化卡片、引用、导出和重试；
- 发生错误时只显示英文通用错误；
- 移动端信息不可读、输入框被键盘遮挡或操作按钮过小。
