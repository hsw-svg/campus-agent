# 修复工作区资料选择与学情分析入口

## Goal

让教师在新对话中可以立即看到并选择之前上传的工作区资料；“分析学情”必须使用用户明确选择的真实资料并进入后端智能体流程；同时清晰区分工作区资料和当前对话附件，避免资料已存在但界面显示为空的误解。

## Confirmed Findings

- `useWorkspaceChat.clearChat()` 当前会清空统一的 `attachments` 状态，因此新对话连工作区资料也不会显示。[apps/web/src/hooks/useWorkspaceChat.ts:161-170]
- `refreshResources()` 需要 `conversationId`，且新对话只在首次发送后才会刷新资源。[apps/web/src/hooks/useWorkspaceChat.ts:103-109, 188-236]
- 教师端快捷“分析学情”入口调用旧的 `startAnalysis()` 本地演示流程，没有发送选中的附件 ID。[apps/web/src/components/TeacherWorkspace.tsx:111, 520-527]
- 工作区上传会保存为 `scope=workspace` 且 `conversation_id=null`；它不应被显示为当前对话附件。[apps/api/app/api/attachments.py:68-72]

## Requirements

### R1. 工作区资料在新对话中可见

- 前端独立维护工作区资料和当前对话附件。
- 切换到新对话时只清空当前对话附件、成果和任务选择，不清空工作区资料。
- 工作区资料可在没有 `conversationId` 的新对话中加载、勾选和参与任务。
- 只有明确勾选的附件 ID 才能进入发送请求；不得隐式把全部工作区资料作为上下文。

### R2. 工作区上传不制造空对话

- 工作区资料提供独立的读取/上传 API，不要求先创建对话。
- 现有带 `conversationId` 的对话附件 API 保持兼容。
- 继续使用现有工作区权限校验、解析状态和对象存储流程，不新增数据库字段或账号能力。

### R3. 学情分析使用真实流程

- “分析学情”快捷入口必须使用当前选中的学情表。
- 未选择可用表格时，按钮给出明确提示，不执行本地假分析或无资料请求。
- 选中资料后通过现有 `sendMessage`/SSE/Artifact 流程执行，结果以服务端返回为准。
- 移除或绕开旧的硬编码文件名、定时器进度和演示报告路径。

### R4. 资料分组语义清晰

- “工作区资料库”表示跨对话可见的资料。
- “当前对话附件”表示只属于当前对话的资料；新对话为空是正常状态，但不应遮蔽工作区资料。
- “当前任务资料”显示实际勾选项，并明确提示只有勾选项会发送。

## Acceptance Criteria

- [x] 新建对话后，之前上传的工作区资料立即显示且可勾选。
- [x] 新建对话不继承旧对话附件、成果或已选 ID。
- [x] 新对话上传工作区资料不会产生无消息的空对话。
- [x] 未选资料点击“分析学情”不会启动分析，并显示可操作提示。
- [x] 选中一份可用学情表后，分析请求包含且只包含该附件 ID，结果来自真实 SSE/Artifact。
- [x] 工作区资料和当前对话附件在右侧面板中分组展示，空状态文案准确。
- [x] `apps/web` 的 lint/build 通过；后端相关测试通过；浏览器回归覆盖上述关键路径。

## Out of Scope

- 不新增登录、账号、权限角色或数据库迁移。
- 不改变后端学情统计算法和 Artifact 数据结构。
- 不将所有工作区资料自动加入任务上下文。

## Latest Requirement Amendment (2026-07-18)

- 教师工作台右侧不再显示资料选择功能区。
- 同一课程内的任务默认使用该课程可见的全部资料（课程资料、通用资料和当前对话附件）。
- 教师端不再要求勾选资料；前端发送当前已知资料 ID，后端在附件 ID 为空或资料尚未完成加载时按课程范围兜底。
- 无课程的独立任务、学生端和行政端继续保留显式资料选择语义。
