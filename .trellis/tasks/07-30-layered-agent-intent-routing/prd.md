# 分层智能体意图路由

## Goal

将现有以规则打分为主、LLM 兜底的智能体路由，升级为“语义嵌入候选召回 + Intent LLM 最终判定”的分层架构，提高自然语言意图识别准确率，并使新增智能体主要通过注册意图描述和示例完成，而不是持续扩展集中式关键词规则。

## Background

- 当前路由已支持手动指定智能体、上下文继承、缺失输入提示和普通聊天降级。
- 现有自动路由依赖集中式规则加权，并通过 Intent LLM 兜底；PPT、教案设计、学情分析等相近意图需要显式优先级和抑制条件。
- 当前角色白名单在 `apps/api/app/agents/registry.py` 中静态注册，共 18 个智能体；已有 OpenAI-compatible Embedding 与 Chat Provider，可复用现有模型适配层。
- 当前前端没有候选智能体确认控件；`requires_confirmation=true` 会让 SSE 流以错误结束。历史会话 `0543f910-e3e` 已将模型异常和低置信度行为定为普通聊天降级，避免不可操作的确认死路。
- 本次只调整后端智能体意图识别与扩展契约，不新增账号、权限、工作区、对话或前端业务能力。

## Requirements

- 自动路由采用分层决策：语义嵌入负责从已注册智能体中召回少量候选，Intent LLM 只在候选集合内做结构化最终判定。
- 除手动选择外，嵌入相似度无论多高都不得直接触发专家智能体；每次自动选择必须由 Intent LLM 在召回候选内完成最终判定。
- 智能体注册信息应包含路由所需的语义描述和代表性意图示例，使新增智能体无需修改集中式关键词评分函数即可参与自动路由。
- 智能体路由元数据采用随代码发布的声明式注册，不新增数据库表、管理 API 或运行时动态注册入口。
- 手动指定智能体继续拥有最高优先级，不经过自动意图判定。
- 保留对会话上下文、附件/资料类型和智能体必需输入的支持；这些结构化证据不得退化为仅依赖文本嵌入。
- 保持现有 `RouteDecision` 对调用方的兼容性，包括智能体、置信度、原因、缺失输入、来源选择和确认语义。
- 嵌入或 Intent LLM 不可用、超时或返回非法结构时必须稳定降级，不得导致对话请求整体失败。
- 嵌入服务不可用、输出非法或候选召回失败时，Intent LLM 必须退化为在当前角色全部已注册智能体中判定；只有 Intent LLM 也失败、输出非法或低置信度时才进入普通聊天降级。
- 在没有确认 UI 的当前产品形态下，自动路由低置信度或模型故障不得返回阻塞式确认状态；应保留候选和原因后进入普通聊天，且不得误调用专家执行器。
- 路由过程应提供足够的可观测原因，便于定位候选召回、最终判定和降级行为。
- 配置必须通过 `app.core.config.Settings` 获取，不硬编码模型地址、密钥或模型名称。
- Intent LLM 必须始终复用现有 Chat Provider 与 `CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL` 配置，不新增独立 Intent 模型配置。
- 单条消息最多路由到一个主智能体；Intent LLM 可返回一个候选智能体或 `null`，本期不支持多智能体串联、并行执行或产物合并。
- 路由输入输出变化应同步共享契约或 API 契约，稳定错误继续使用 `AppError` JSON 结构。

## Acceptance Criteria

- [x] 已注册智能体可以通过声明式语义元数据参与嵌入召回，新增智能体无需修改集中式关键词评分逻辑。
- [x] 自动路由先生成有序候选集合，再由 Intent LLM 在候选内返回结构化决策；LLM 不能选择候选外智能体。
- [x] 手动指定、清晰意图、相近意图、短追问继承、附件证据、缺少必需输入和普通聊天均有可执行回归测试。
- [x] 嵌入服务异常、Intent LLM 异常、低置信度和非法模型输出均有明确、经过测试的降级行为。
- [x] 现有 API 调用方无需因内部路由分层而改变，除非最终设计明确记录兼容迁移。
- [x] 路由回归测试只使用 Fake Provider，不产生真实或可计费的外部模型调用。
- [x] 本任务不新增数据库表或字段，不需要 Alembic 迁移；API 相关单元与回归测试通过。

## Out of Scope

- 新增账号、登录、JWT、角色权限或新的前端确认流程。
- 为路由引入服务端文档转换或更改 PPTX 预览架构。
- 本任务之外的智能体执行器、产物生成逻辑和页面视觉重构。
- 多智能体编排、工作流状态机、跨智能体失败恢复和多产物合并。
- 数据库驱动的智能体目录、后台管理界面和无需发布代码的运行时智能体注册。

## Notes

- 历史会话 `6c635272-d3e` 记录了现有“规则 + LLM 兜底”架构及相近意图抑制逻辑；本任务将正确业务结果作为回归基线，而不是保留其实现方式或继续堆叠规则。
- 本任务是一条不可分割的后端路由链，不拆分父子任务：注册画像、候选召回、最终判定和 API 接线必须一起验证才有独立用户价值。
