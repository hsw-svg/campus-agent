# 学生简历助手

## Goal

在学生端左侧菜单新增独立“简历助手”，让学生上传自己的简历，结合本人真实课程学习进度获得可执行的简历修改建议，并为后续模拟面试能力提供明确入口。

## Requirements

- 学生端左侧菜单新增“简历助手”，与学习中心、课程中心、校园中心并列切换，不使用对话框承载主功能。
- 简历助手支持上传并解析简历，首期复用现有附件能力支持 `.pdf`、`.docx`、`.txt`、`.md`，单文件不超过 25 MB。
- 扫描版 PDF 无可提取文本时必须给出明确提示，不得对空内容生成建议。
- 简历数据仅限当前匿名学生工作区使用，不得读取教师、行政或其他工作区资料。
- 分析必须结合：
  - 学生主动上传的当前简历内容。
  - 当前学生工作区真实的课程、章节完成度、薄弱知识点和学习进度。
- 课程依据由学生确认：
  - 默认选中当前工作区所有已开始学习的课程。
  - 学生可取消无关课程，仅将本次选中的课程进度提交给 AI。
  - 未开始课程在页面中可见但不可勾选，后端也不得将其作为能力证据。
- AI 输出至少包含：
  - 简历问题清单。
  - 分模块修改建议。
  - 可直接参考的改写示例。
  - 课程学习经历与简历能力描述之间的匹配建议。
  - 一份完整的优化后简历草稿。
- 优化后简历草稿只能重组、压缩和润色当前简历及课程进度中已有的事实；证据不足但确有必要补全的内容使用“待补充”占位，不得自行补写。
- 完整草稿和各个草稿模块均支持一键复制，并保留适合粘贴到常见编辑器的 Markdown 风格层级。
- 页面提供可选的目标岗位和职位描述（JD）：
  - 填写后生成岗位定向的关键词匹配、能力差距与改写建议。
  - 未填写时结合课程进度生成通用简历优化建议。
  - 目标岗位和 JD 均属于当前学生工作区私有数据。
- 简历上传和 AI 分析是两个明确阶段：
  - 上传成功后先展示文件名、解析状态和可编辑的目标岗位/JD。
  - 只有学生点击“开始分析”后才调用模型。
  - 分析失败可原地重试，不要求重新上传简历。
- 不得虚构学生未在简历或课程进度中出现的项目、实习、证书、成绩或技能。
- 分析结果应持久化，刷新页面后仍可查看最近一次简历及其建议。
- 简历助手采用与教师工作台相似的“主内容 + 右侧智能体记录”布局：
  - 主内容区负责当前简历上传、岗位/JD、课程选择和完整分析报告。
  - 右侧记录区展示历次简历分析的时间、岗位、状态和摘要。
  - 右侧默认展示最近 6 条，可展开查看全部记录，并支持删除单条分析记录。
  - 点击历史记录在主内容区恢复对应的完整分析结果。
  - 完整报告只在主内容区渲染，右侧不重复展示整份内容。
- 历史分析记录不自动过期；学生主动删除工作区时随工作区数据级联清理。
- 首期维护一个当前简历；重新上传后替换当前简历入口，但已经生成的历史分析记录继续保留。
- 页面提供“模拟面试”入口，但本期仅作为预留功能：
  - 清晰标注“即将上线”。
  - 不发起伪造的面试流程或 AI 请求。
- 延续 React、TypeScript、Tailwind CSS、lucide-react、Motion、FastAPI、SQLAlchemy 和现有模型适配器，不引入重复框架。

## Acceptance Criteria

- [ ] 左侧菜单可进入独立简历助手页面，切换后不显示学习聊天或校园资讯内容。
- [ ] 可上传并解析受支持格式的简历，展示上传、解析中、成功和失败状态。
- [ ] 解析成功不会自动调用 AI；只有点击“开始分析”才产生分析请求。
- [ ] 无文本扫描版 PDF 不会进入 AI 分析，并显示可操作提示。
- [ ] 分析请求只使用当前学生的简历和课程学习进度。
- [ ] 已开始课程默认选中，学生可取消无关课程，后端只读取本次明确选择且属于当前工作区的课程。
- [ ] 未开始课程有明确状态但不可勾选；伪造、跨工作区或未开始课程 ID 均不会进入分析上下文。
- [ ] AI 建议能区分原简历问题、修改建议、改写示例和课程能力匹配。
- [ ] 分析结果包含完整的优化后简历草稿；草稿只使用有依据的信息，缺失内容标记为“待补充”。
- [ ] 可复制完整草稿或单独复制某个草稿模块，复制内容保留清晰的 Markdown 风格层级。
- [ ] 填写目标岗位或 JD 后输出定向建议；不填写时仍可完成通用分析。
- [ ] 没有课程学习记录时仍可分析简历，但明确说明缺少课程进度依据。
- [ ] AI 输出不包含无证据的虚构经历。
- [ ] 刷新后可恢复最近一次简历与分析结果。
- [ ] 右侧智能体记录可显示并打开历史简历分析，完整报告只在主内容区展示一次。
- [ ] 右侧默认展示最近 6 条，可展开全部并删除单条分析记录；未主动删除的记录不会自动过期。
- [ ] 重新上传可替换当前简历，已有分析历史不会随之消失。
- [ ] “模拟面试”入口可见且标注为预留，不会发起后端执行。
- [ ] 桌面端与移动端布局无溢出，菜单均可到达。
- [ ] 后端测试、前端 lint 与生产构建通过。

## Confirmed existing capabilities

- 后端已支持工作区隔离的附件上传、对象存储、PDF/DOCX/TXT/Markdown 文本解析、分块与索引。
- 学生智能体注册表和路由中已存在 `resume_helper` 定义、手动选择与缺少简历材料的输入校验，但尚未发现对应的专用执行器和结构化输出实现。
- 课程中心已提供工作区范围内的课程摘要、章节进度和证据驱动薄弱知识点，可作为简历分析的学生能力依据。
- Artifact 已可持久化结构化 AI 结果，适合承载简历分析报告。
- 赛题与项目文档已明确将简历修改、模拟面试列为学生端扩展能力，并要求只读取学生主动提供的资料。

## Out of scope

- 真实语音或视频模拟面试。
- 招聘平台投递、岗位抓取、账号体系、就业档案或教师查看学生简历。
- DOCX、PDF 等格式的简历模板套用与文件导出。
- 自动伪造、补全或夸大学生经历。

## Decisions

- 目标岗位与职位描述为可选输入；有值时定向分析，无值时通用分析。
- 简历解析成功后由学生显式点击“开始分析”，不自动调用模型。
- 已开始课程默认选中，学生可按本次岗位目标取消无关课程。
- 首期使用一个当前简历；右侧智能体记录保留历次分析，点击后在主内容区恢复报告。
- 历史记录默认显示最近 6 条、可查看全部并单条删除；记录不自动过期，随工作区删除统一清理。
- 首期生成完整的优化后简历草稿，但仅允许润色和重组已有事实，缺失信息使用“待补充”标记。
- 首期支持完整草稿和分模块复制，保留 Markdown 风格排版；不提供 DOCX/PDF 文件生成或下载。
- 未开始课程只展示状态、不允许选择；只有当前工作区已开始课程可作为简历分析证据。
