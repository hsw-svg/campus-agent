# 修复学生端课程对话与伴学推荐

## Goal

修复学生学习中心的课程会话连续性、内部服务品牌泄漏和静态推荐问题，使学生刷新、切换页面或重新进入课程后能继续原课程/章节对话，并获得符合当前学伴角色和课程内容的推荐问题。

## Background

- 后端已经通过 `Conversation.course_id` 与 `Conversation.chapter_id` 持久化课程和章节归属，创建接口也验证课程/章节所有权；本次不需要新增账号、权限或课程关系模型。证据：`apps/api/app/conversations/models.py:26`、`apps/api/app/api/conversations.py:128`。
- 学生端进入课程、完成章节或返回学习中心时会调用 `clearChat()`，但没有按课程/章节恢复已存在的最近会话；`learningCourse` 和 `learningChapterId` 只存在 React 内存中，刷新后丢失。证据：`apps/web/src/components/StudentWorkspace.tsx:178`、`apps/web/src/components/StudentWorkspace.tsx:201`、`apps/web/src/components/StudentWorkspace.tsx:328`。
- 浏览器虽按角色持久化匿名 workspace token，但当前激活角色只存在 React 内存中；整页刷新会先退回角色选择页，阻断自动恢复链路。证据：`apps/web/src/App.tsx:14`、`apps/web/src/App.tsx:17`。
- 最近对话弹窗只在当前课程存在时展示该课程当前章节的对话，否则只展示未绑定课程的对话；从课程上下文外无法通过该入口恢复课程对话。证据：`apps/web/src/components/StudentWorkspace.tsx:466`。
- 学伴角色指令和角色菜单直接出现 `DeepTutor`；助手输出经 SSE 原样显示并原样持久化，没有学生可见品牌归一化。证据：`apps/web/src/components/StudentWorkspace.tsx:53`、`apps/web/src/components/StudentOrbitHome.tsx:232`、`apps/api/app/services/conversations.py:417`、`apps/api/app/services/conversations.py:521`。
- 推荐问题是固定三条，不使用当前角色、课程、章节或知识点。证据：`apps/web/src/components/StudentOrbitHome.tsx:254`。

## Requirements

### R0. 课程上下文与教材知识库

- 学生课程中心继续以数据库中的 `Course`、`CourseChapter` 和学习进度为唯一数据源；前端不得维护第二套课程事实。
- 学生提问必须提交当前 `course_id` 与 `chapter_id`。后端以 Conversation 的持久绑定为准，并拒绝与当前会话不一致的课程或章节。
- 后端把课程名称、简介、分类、当前章节名称、章节摘要和知识点作为受信任课程元数据注入模型上下文。
- 没有教材时，课程问答可以使用课程元数据回答课程范围、章节目标和基础知识导览；不得伪造教材原文、页码或教师未提供的细节。
- 学生可把支持的文档上传为课程教材。教材使用现有 workspace Attachment 管线并通过 `Attachment.course_id` 持久绑定，不因会话删除而丢失。
- 进入课程后，前端默认加载并选择该课程全部教材；其他课程教材不得进入当前对话。
- 课程教材完成本地解析后，后端自动调用 DeepTutor 1.5.8 的真实知识库 create/upload 接口。每门课程使用稳定知识库名称，后续教材追加到同一知识库。
- DeepTutor 接受任务后持久记录知识库名称、状态和任务 ID；上游不可用不得回滚已经成功的本地教材上传，但必须返回可见的降级状态。

### R1. 课程/章节会话连续性

- 新建学生对话时继续使用现有 `course_id` 与 `chapter_id` 绑定，不新增第二套会话存储。
- 学生进入某课程/章节时，自动打开该课程/章节最近更新的对话；没有匹配会话时展示空学习会话，并在首次提问时创建绑定对话。
- 页面刷新后，若存在学生课程对话，恢复最近更新课程对话对应的课程、章节和消息。
- 整页刷新后恢复刷新前的激活角色，并复用该角色已经校验的匿名 workspace token；用户主动“切换角色”时清除自动恢复标记。
- 从其他学生页面或最近对话弹窗返回课程对话时，先恢复该对话的课程/章节上下文，再加载消息。
- 最近对话弹窗应能看到所有非简历助手学生对话，不因当前是否已选课程而隐藏课程对话；课程对话应显示可辨识的课程/章节上下文。
- 切换课程、章节和并发加载时，较晚发起的用户选择优先，旧请求不得覆盖新上下文。

### R2. 学生可见品牌归一化

- 学生端角色菜单、角色指令和学生可见回答不得出现 `DeepTutor`、`Deep Tutor` 或对应“助手”组合；统一使用“智汇校园”或“AI 学伴”措辞。
- 过滤同时覆盖流式 SSE 片段与最终持久化的 assistant 消息，刷新历史后不得重新出现内部品牌。
- 过滤必须正确处理品牌名称被拆分到多个流式 delta 的情况，不泄漏半截内部品牌，不重复或丢失回答正文。
- 教师/行政的任务语义、Artifact 内容和 DeepTutor 集成 API/工程日志不在本次展示文案替换范围内。

### R3. 角色和课程驱动的推荐问题

- 推荐问题根据四种学伴角色分别采用均衡引导、同伴讨论、研究分析、导师讲授的提问风格。
- 选中课程时，推荐问题至少包含课程名；选中章节时优先包含章节名，并可使用章节知识点生成更具体的问题。
- 角色、课程或章节变化后，三条推荐问题立即更新；点击后继续复用现有问答流程。
- 未选择课程时提供与当前角色一致的通用学习建议，不虚构课程内容。
- 推荐按钮保持键盘可用、中文可读、窄屏可达，不新增前端框架或外部推荐服务。

## Acceptance Criteria

- [x] AC0.1：学生在高等数学/函数、极限与连续中提问“当前课程主要内容”，模型上下文包含正确课程、章节、摘要和知识点；不包含其他课程。
- [x] AC0.2：请求提交的课程或章节与 Conversation 绑定不一致时返回稳定 `422 conversation_course_context_mismatch`，不调用模型。
- [x] AC0.3：课程没有教材时，自动路由到 `course_qa` 不再返回“缺少课程资料”，并可基于课程元数据完成回答。
- [x] AC0.4：学生上传教材后 Attachment 为 workspace scope 且绑定当前课程；重新进入课程后自动列出并选择该教材。
- [x] AC0.5：第一份教材调用 DeepTutor knowledge create，后续教材调用同一课程知识库的 upload；接受任务后保存 `queued` 和 task ID。
- [x] AC0.6：DeepTutor 不可用时本地教材仍可用于现有检索问答，响应显示知识库同步失败/暂不可用，不声称构建成功。

- [x] AC1：课程 A 章节 A1 首次提问后生成的 Conversation 同时含课程 A 与章节 A1；切到课程 B 再回课程 A/A1，原消息自动恢复。
- [x] AC2：刷新学生端后，最近更新的课程对话恢复其课程、章节和完整消息，不创建重复空会话。
- [x] AC3：最近对话弹窗在无当前课程时仍显示课程对话；点击某课程对话后恢复正确课程/章节，其他课程消息不混入。
- [x] AC4：课程/章节没有历史时保持空状态，首次发送只创建一个绑定对话。
- [x] AC5：模拟 `Deep`、`Tutor助手发现……` 分片输出时，SSE 可见内容和持久化历史都不包含内部品牌，正文仍完整。
- [x] AC6：学生端角色菜单、已发送的角色指令投影和回答展示不出现 `DeepTutor` 或 `Deep Tutor`。
- [x] AC7：四种角色在同一课程/章节产生不同推荐文案；切换课程或章节后推荐中的上下文同步变化；无课程时不虚构课程名。
- [x] AC8：新增自动化回归测试通过；后端相关 pytest、前端 TypeScript 测试、`npm.cmd run lint` 与 `npm.cmd run build` 全部通过。
- [x] AC9：桌面和窄屏学生学习中心保持现有星图学习舱布局、最近对话模态和 AI 学伴入口可用。

## Out of Scope

- 新增登录、账号、JWT、选课、班级、工作区权限或真实身份系统。
- 将 DeepTutor 工程模块、API 路径、配置项、容器日志或开发文档改名。
- 新增 LLM 调用专门生成推荐问题；推荐使用可测试的本地确定性模板。
- 改造教师端、行政端会话恢复流程，或重设计学生端整体视觉。
