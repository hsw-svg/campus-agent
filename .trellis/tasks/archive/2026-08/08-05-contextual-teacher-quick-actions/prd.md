# 课程切换驱动教师端快捷任务

## Goal

让教师端课程任务对话框上方的快捷任务跟随当前选中的课程变化，避免所有课程都显示固定的 Python 练习、破冰和测验薄弱点文案。教师切换课程后，应能立即看到与新课程相关的快捷任务，并且点击后仍然创建归属当前课程的新任务。

## Confirmed facts

- `apps/web/src/components/TeacherWorkspace.tsx` 持有 `activeCourseId`、当前课程和 `courseContext`。
- 课程列表已经提供课程名称、描述和类别；当前教师端没有在课程切换时为快捷任务单独请求章节详情的逻辑。
- `useWorkspaceChat` 已将 `courseContext` 传给消息请求，并在课程上下文变化时清理当前对话、重新加载课程资料和课程智能体历史。
- 快捷任务目前分别硬编码在欢迎区、学情分析报告后的操作区和输入框上方标签区，存在重复文案。

## Requirements

### R1. 使用当前课程生成快捷任务文案

当存在当前课程时，快捷任务的显示文案和发送内容必须引用当前课程名称；不得继续固定使用“Python”作为所有课程的练习类型。首版保留三类稳定意图：课堂练习、课堂互动、测验薄弱点分析。

### R2. 无课程时提供安全的通用回退

没有选中课程时，快捷任务使用不带具体学科或课程名称的通用文案，例如“根据本节课目标生成课堂练习”，避免误导教师当前上下文。

### R3. 所有入口使用同一组定义

欢迎区、学情报告后的“继续生成课堂练习”按钮和输入框上方快捷标签必须复用同一组动态快捷任务定义，避免切换课程后不同入口显示或发送不同内容。

### R4. 保持当前课程归属和切换行为

点击快捷任务时，消息仍通过现有 `useWorkspaceChat` 流程发送，使用当前 `courseContext` 创建或继续任务；本次改动不改变历史对话、课程资料筛选和课程切换确认行为。

### R5. 不引入额外服务依赖

首版只使用已有课程上下文和课程列表字段完成动态化，不新增 API、数据库字段、模型调用或运行时依赖。

## Acceptance Criteria

- [x] 切换课程后，输入框上方的三条快捷标签立即显示新课程名称，并且点击发送的新消息内容也引用新课程。
- [x] 欢迎区的“生成课堂练习”和“设计课堂互动”入口与输入框上方标签使用同一组当前课程快捷任务定义。
- [x] 学情分析报告后的课堂练习操作使用当前课程快捷任务，而不是固定的 Python 文案。
- [x] 没有选中课程时，所有快捷任务回退为通用文案，不出现 Python 或上一个课程名称。
- [x] 快捷任务点击后，现有课程归属逻辑保持不变，`createConversation` 仍使用当前课程 ID。
- [x] 前端 lint 和 build 通过。

## Out of scope

- 根据章节目标、测验结果或课程资料生成更细粒度的推荐排序。
- 新增课程章节选择器、快捷任务推荐 API、埋点或模型生成文案。
- 重构教师端其他静态示例内容或学情报告中的演示数据。
