# 学生端交互式书本与学习空间

## Goal

在学生工作台中提供一个围绕 DeepTutor 的“学习空间”，让学生可以从学习概览进入交互式书本，按目录阅读结构化页面，并针对当前页面进行流式问答。整体沿用校园智能助手已有的青绿色视觉语言和工作台布局，满足竞赛现场“可快速理解、可连续演示、服务异常可恢复”的目标。

## Requirements

- 在学生端新增“学习空间”入口，展示交互书本数量、页面完成数、学习笔记/收藏问题数量、最近继续学习位置和知识库状态。
- 将现有“交互教材”升级为书本阅读工作区：书本搜索/筛选、书本卡片、目录侧栏、阅读进度、上一页/下一页、页面正文，以及常见 DeepTutor 内容块（正文、提示、重点、练习/问答卡）的可读展示。
- 在阅读页提供“页面问答”侧栏，通过现有 FastAPI 的同源 WebSocket 代理连接 DeepTutor；请求必须携带书本和页面上下文，浏览器不得直接访问 DeepTutor 8001 端口。
- 支持从学生端输入学习主题创建交互式书本，并可选择现有知识库；创建失败或 DeepTutor 不可用时显示明确的降级提示，不影响课程学习中心。
- 支持学生标记页面完成、保存本页学习笔记、保存问答问题；学习空间从本地持久化状态生成继续学习和学习记录，避免为演示引入新的账号/数据库业务模型。
- 复用现有 `src/api.ts` 的 DeepTutor 请求、响应归一化和 WebSocket URL 约定；不得在组件中散落未类型化的上游 payload 解析。
- 不改变现有课程学习、聊天、校园中心、简历助手和后端 DeepTutor 进程编排；不暴露 8001，也不复制上游 DeepTutor 的 Next.js 页面或样式。

## Acceptance Criteria

- [ ] 学生侧边栏和移动端导航都能进入“学习空间”和“交互教材”，已有学习中心与课程入口行为不回归。
- [ ] 学习空间可在无书本、无知识库、DeepTutor 请求失败三种状态下稳定渲染，并能从最近学习记录打开对应书本。
- [ ] 交互教材可加载书本、目录和页面；切换目录后页面内容、阅读进度和页面问答上下文同步更新。
- [ ] 页面问答支持发送、流式追加、完成、错误和关闭连接；刷新页面后不得遗留失控的 WebSocket。
- [ ] 页面完成、笔记和收藏问题在同一浏览器刷新后保留，并按当前书本/页面显示；不存在真实用户时不新增后端持久化表。
- [ ] 创建书本会显示 loading、成功后的书本刷新和失败提示；没有 token 时不会发起请求。
- [ ] `npm.cmd run lint` 与 `npm.cmd run build` 通过；相关现有 API/适配层检查不受影响。
- [ ] 变更只发生在新分支 `codex/student-deeptutor-learning-space`，提交前不覆盖工作区其他修改。
