# 实施计划：学情分析结果页面平铺展示

## 代码步骤

1. 核对 `Artifact`、`Message` 和 `useWorkspaceChat.openConversation` 的会话关联，确认页面级 selector 只能读取当前活动会话的学情分析 artifact。
2. 为独立学情分析入口增加最近结果恢复逻辑，并将独立结果层与通用工作台对话隔离。
3. 在独立结果层复用 `LearningAnalysisReport`，隐藏任务消息、任务输入、追问、课程/历史管理，并提供关闭和重新分析动作。
4. 增加结果卡片返回首页交互；首页展示历史分析记录并提供新文件上传入口，历史记录点击后恢复对应 artifact。
5. 保留课程任务的报告兼容路径，同时确保独立学情分析不在通用任务对话中重复渲染。
6. 验证新建任务、切换课程、打开历史结果、返回首页、上传新文件和重新分析等状态，必要时补充最小的可执行回归检查或稳定的 DOM 语义。
5. 运行 `npm.cmd run lint`、`npm.cmd run build`、`git diff --check`，并检查变更只涉及本任务范围与既有未提交修改兼容。

## 风险与对策

- **恢复期间短暂显示旧结果**：报告条件同时校验活动会话 ID和 artifact 会话 ID，并沿用 hook 的版本号竞态保护。
- **独立页再次混入任务管理**：结果层使用单独的覆盖容器并将底层工作台设为 inert；检查独立层内不存在消息、输入、追问和历史面板节点。
- **报告重复或消息出现空白气泡**：独立层只调用一次 `LearningAnalysisReport`，通用任务路径不渲染独立报告；检查 DOM 中独立层报告实例数量。
- **切换任务时页面高度跳动**：报告区使用稳定的块级布局和同一滚动 owner，避免在消息气泡中动态改变 max-width。
- **现有历史详情受影响**：只抽离工作台消息分支，`HistoryDetailModal` 的报告分支保持不变。
